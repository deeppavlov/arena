# Пример адаптера

`main.py` содержит два простых способа запуска: подготовка контекста с ответом внутренней модели и обычная Python-программа без LLM. Режим задаёт доверенный оператор через профиль `DockerRunner.uses_model`. Граница контейнера, таймауты и обязательные измерения ресурсов описаны в [контракте runner](../common/runner-contract.md).

В модельном режиме пример читает `/candidate/prompt.md`. Необязательный `/candidate/prepare.py` получает через stdin `input`, `assets_dir: "/assets"`, фиксированную `model`, адрес `model_base_url` данного запуска и `model_request_timeout` в секундах, затем возвращает `{"context":"Подготовленный контекст"}`. При наличии параметров кандидата они передаются отдельным полем `parameters`. Все модельные вызовы подготовки идут через переданный адрес gateway с тем же таймаутом и попадают в общий учёт решения. Технические ошибки повторяет gateway, до пяти повторов после первой попытки. Параметры генерации и ключ остаются в gateway.

В режиме `uses_model=False` запускается `/candidate/solve.py`. Он получает JSON с `input`, `assets_dir: "/assets"` и, если они заданы, `parameters`; возвращает JSON `{"answer":"Окончательный ответ"}`. Программа исполняется только в одноразовом контейнере, без сети, конфигурации модели и gateway. Например:

```python
import json
import sys

task = json.load(sys.stdin)
print(json.dumps({"answer": task["input"].upper()}))
```

Для обоих режимов stdout содержит один JSON с ответом, не более 1 MiB. Ошибка программы, неверный формат и превышение времени — ошибки исполнения. Штатный пустой ответ передаётся метрике. Доступны стандартные Python-модули; дополнительные зависимости оператор устанавливает в image до фиксации кампании. Другие языки и внешние харнесы используют собственный закреплённый образ с тем же протоколом.

Кандидат может содержать `solution.json`:

```json
{"harness":"program","parameters":{"iterations":3}}
```

`harness` выбирается только из реестра, который настроил оператор. Поле `parameters` необязательно и должно быть JSON-объектом с конечными числами. Параметры передаются вложенным объектом и не меняют образ, сеть, mounts, модель или gateway. При отсутствии манифеста используется профиль по умолчанию. Допустимость изменений харнеса, параметров или файлов решения задаёт промпт кампании; фиксированный режим может использовать один профиль. Полный реестр и его digest сохраняются оценщиком в provenance, а ID и параметры входят в замороженные файлы кандидата.

По умолчанию подготовка модельного контекста может занимать 48 часов, одна модельная попытка — шесть часов. Runner ждёт gateway до завершения всех допустимых попыток; оценщик ограничивает весь пример, включая выполнение `solve.py`, семью сутками. Затраты токенов модельного режима берутся из доверенного журнала gateway, у режима без модели они равны нулю. Время обоих режимов измеряется снаружи контейнера. Для многочасовых прогонов применяй [протокол ожидания](../common/long-runs.md).

Для сборки из корня репозитория:

```bash
docker build -f runner/Dockerfile -t arena-runner:local .
docker image inspect arena-runner:local --format '{{.Id}}'
```

Полученный `sha256:...` укажите в `ARENA_RUNNER_IMAGE` или в операторском реестре. На другом Docker-хосте образ заранее доставляется с тем же ID либо указывается через registry digest. Воспроизводимый релиз также фиксирует digest базового Python image. Контейнеры и права описаны в [инструкции развёртывания](../deploy/README.md).
