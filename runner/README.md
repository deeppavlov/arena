# Пример адаптера

`main.py` — минимальный фиксированный харнес: подготовка контекста и один корректно полученный ответ модели. Технические ошибки обращения повторяет gateway, до пяти повторов после первой попытки. Оператор может заменить image реализацией своего харнеса до начала кампании. Граница контейнера, таймауты и обязательные измерения ресурсов описаны в [контракте runner](../common/runner-contract.md).

Пример читает `/candidate/prompt.md`. Необязательный `/candidate/prepare.py` получает через stdin `input`, `assets_dir: "/assets"`, фиксированную `model`, адрес `model_base_url` данного запуска и `model_request_timeout` в секундах, затем возвращает `{"context":"Подготовленный контекст"}`. Все модельные вызовы подготовки идут через переданный адрес gateway с тем же таймаутом и попадают в общий учёт решения. Доступны стандартные Python-модули; дополнительные зависимости оператор устанавливает в image до фиксации кампании. Параметры генерации и ключ остаются в gateway.

По умолчанию подготовка может занимать 48 часов, одна модельная попытка — шесть часов. Runner ждёт gateway до завершения всех допустимых попыток; оценщик ограничивает весь пример семью сутками. Затраты токенов берутся из доверенного журнала gateway, а время измеряется снаружи контейнера. Для многочасовых public-прогонов применяй [протокол ожидания](../common/long-runs.md).

Для последующей сборки из корня репозитория:

```bash
docker build -f runner/Dockerfile -t arena-runner:local .
docker image inspect arena-runner:local --format '{{.Id}}'
```

Полученный `sha256:...` укажите в `ARENA_RUNNER_IMAGE`. На другом Docker-хосте образ заранее доставляется с тем же ID либо указывается через registry digest. Воспроизводимый релиз также фиксирует digest базового Python image. Контейнеры и права описаны в [инструкции развёртывания](../deploy/README.md).
