# Правила арены

Сначала прочитай README.md. Затем применимые common/ и промпт своей роли.

- Арена универсальна: кейсы и способы решения задаются файлами и промптами. Не добавляй зависимость от конкретного харнеса или домена в общий протокол.
- Делегируй независимые направления исследователям в отдельных worktree. Следуй common/orchestration.md и common/IMMUNE.md.
- Не меняй фиксированные модель, харнес, метрику, эталоны и split внутри кампании.
- Все данные обрабатываются только внутренними моделями. Solver и judge — одна модель.
- Один корректно полученный ответ на пример; три независимых корректных judging каждого критерия. При ошибках модельного запроса — до пяти повторов с прежними входом и настройками; валидный ответ ради балла не повторяется.
- Токены и время решения измеряй обязательно, включая подготовку и повторы; затраты судьи храни отдельно. При равном балле применяй общее правило ранжирования из common/public-evaluation.md.
- Долгие задания и субагентов жди по common/long-runs.md: проверь первый результат, рассчитай остаток и ожидай весь срок без промежуточного опроса моделью.
- Public-подвыборки допустимы. Приватные данные, отдельные оценки и трейсы не добываются и не используются для изменения кандидатов.
- Новые private-попытки не открываются переименованием кампании или кандидата.
- Отрицательные результаты сохраняй вместе с гипотезой и числами.
- Никогда не сохраняй секреты или private в Git, образах и общем MLflow.
- Для детерминированного кода сначала тест; для качества сначала критерий и измерение. Не запускай реальные модели без задачи на эксперимент и зафиксированного бюджета.
- Перед передачей изменений: uv run ruff check ., uv run pyright, uv run pytest и uv run python -m evaluator.smoke.
