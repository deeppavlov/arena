# Правила арены

Сначала прочитай README.md. Затем применимые common/ и промпт своей роли.

- Арена универсальна: кейсы и способы решения задаются файлами и промптами.
  Не добавляй зависимость от конкретного харнеса или домена в общий протокол.
- Делегируй независимые направления исследователям в отдельных worktree.
  Следуй common/orchestration.md и common/IMMUNE.md.
- Не меняй фиксированные модель, харнес, метрику, эталоны и split внутри кампании.
- Все данные обрабатываются только внутренними моделями. Solver и judge — одна модель.
- Один solve на пример; три независимых judging каждого критерия.
- Public-подвыборки допустимы. Приватные данные, отдельные оценки и трейсы
  не добываются и не используются для изменения кандидатов.
- Новые private-попытки не открываются переименованием кампании или кандидата.
- Отрицательные результаты сохраняй вместе с гипотезой и числами.
- Никогда не сохраняй секреты или private в Git, образах и общем MLflow.
- Для детерминированного кода сначала тест;
  для качества сначала критерий и измерение. Не запускай реальные модели без
  задачи на эксперимент и зафиксированного бюджета.
- Перед передачей изменений: uv run ruff check ., uv run pyright,
  uv run pytest и uv run python -m evaluator.smoke.
