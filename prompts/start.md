# Старт арены

Ты запускаешь исследование в этом репозитории по выбранному пользователем кейсу. Прочитай `README.md`, `AGENTS.md`, описание кейса, его метрику и разрешённые изменения, затем `common/research-protocol.md`, `common/orchestration.md` и `common/IMMUNE.md`.

Сначала восстанови состояние существующей кампании. Если её нет, зафиксируй постановку, исходные версии и неизменяемые условия в `runs/<campaign>/campaign.md`. Не запускай модельные измерения без указанного кейса, внутреннего endpoint и выделенных ресурсов; недостающую настройку обозначь явно. Не подставляй конкретную модель, харнес или кейс из примеров документации.

Работай как оркестратор по `prompts/orchestrator.md`. Начни с экспертной проверки постановки и baseline, затем раздели поиск на независимые гипотезы. Используй штатные субагенты и worktree, если они доступны; иначе выполняй роли последовательно с передачей контекста через файлы. Новый фреймворк оркестрации не требуется.

Тестируемые модель и харнес фиксированы; решатель и судья используют одну внутреннюю модель в разных запросах. Все обращения к моделям с данными кейса остаются внутри разрешённого контура, в том числе на public. Проверяй один ответ на пример тремя отдельными запросами по каждому критерию. Для разведки разрешены подмножества public; для отбора нужен общий набор.

Public-трейсы служат для объяснения механизма ошибок, а не для зашивания ответов. Сохраняй гипотезы, версии, неудачи и решения. Зафиксированное оператором число финалистов, по умолчанию пять (от одного до пяти), замораживается одним списком до private. После первого допуска нельзя менять число и состав. Каждый кандидат допускается один раз, итог раскрывается после успешного завершения всей серии. Не ищи private-данные и доступ к административным средствам оценщика.

При остановке оставь сохранённое состояние: известные факты, незавершённые проверки, текущие работники, ссылки на результаты и следующий шаг. Не называй непроверенный подход победителем.
