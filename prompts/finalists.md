# Заморозка финалистов

Заверши public-поиск по `common/research-protocol.md`. Проверь, что кандидаты прошли независимое ревью и сравниваются на одном сохранённом public-наборе при одинаковых условиях. Разведочные оценки на разных подмножествах не используй как итоговый рейтинг.

Запиши в `runs/<campaign>/selection.md` правило отбора, таблицу public-результатов, ограничения и выбранных кандидатов. Для каждого обязательны балл, токены и время решателя, число попыток без usage; судейские расходы записываются отдельно. При равном балле примени `evaluator.ranking.choose_winner` по `common/public-evaluation.md`: полный учёт, меньше токенов, меньше времени, стабильный ID. Их число фиксирует оператор заранее: по умолчанию пять, допустимо от одного до пяти. Для каждого сохрани идентификатор, неизменяемую ревизию и хеш передаваемого артефакта, конфигурацию, зависимости и ссылки на замеры. Не заполняй список дубликатами ради формального числа. Если отбор ещё не обоснован, явно оставь его незавершённым.

Зафиксируй весь список до первого private-допуска. Передай его клиенту `python -m evaluator.client` по инструкции в README. После первого допуска нельзя менять число и состав. Каждый кандидат допускается один раз; повтор с новым названием, изменённым содержимым или новой кампанией для обхода лимита запрещён. Повторная доставка идентичного списка возвращает прежнее состояние без нового запуска. При инфраструктурной ошибке серия остаётся закрытой с израсходованным допуском; API не возобновляет её и не сбрасывает квоту. Диагностика доступна только оператору в изолированном контуре.

До успешного завершения всей серии клиент возвращает только статус. Не запрашивай промежуточные оценки, private-трейсы, вопросы, ответы и эталоны. Итоговые агрегаты раскрываются один раз, private-набор переходит в `sealed` и больше не принимает кандидатов.

После принятой отправки приватный сервис самостоятельно выполняет прогоны и выбирает победителя по баллу, токенам и времени решателя. Не управляй отдельными запросами и не опрашивай статус часто. Рассчитай ожидание по публичным замерам и доступным до запуска сведениям о размере приватной серии либо используй операторский интервал из `common/long-runs.md`. После ожидания прочитай итог; корректный принятый пакет не нужно отправлять заново ради продолжения.

Подготовь итог: победитель по зафиксированному правилу, public/private-агрегаты, замороженный артефакт, известные ограничения и воспроизводимые условия. Если серия не завершена, сообщи статус и отсутствующие результаты без объявления победителя. Публикация отчёта не означает развёртывания победителя в продукте.
