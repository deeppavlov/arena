# Заморозка финалистов

Используй накопленные результаты по `common/research-protocol.md`. Число входных финалистов и число итоговых решений private заданы отдельно и точно; выход не превышает вход. Оркестратор планирует воронку под эти числа с начала поиска. Не уменьшай число автоматически и не заполняй список дубликатами.

Используй явно переданный каталог кампании `<campaign_dir>`; для новой кампании его выбирает подготовка, например `cases/<case>/campaigns/<campaign>` или `runs/<campaign>`. Для возобновления сохраняй прежний путь к состоянию и общему журналу.

Сначала проверь условие завершения поиска из `common/research-protocol.md`: лимит предложений исчерпан либо есть явная команда человека остановить поиск с сохранённым источником. Сверь единый журнал: число предложенных решений, оставшиеся места до лимита и выполняющиеся проверки. Сам факт наличия нужного числа финалистов не разрешает private. Если основание отсутствует, вернись к поиску; при блокировке сохрани незавершённое состояние без отправки. Если private уже принят, используй только статус прежней серии и не формируй новую попытку.

После явной команды человека остановить поиск новые проверки не запускаются, включая ожидающие в очереди и дополнительные проверки устойчивости. Дождись только уже выполняющихся. Сравнение свидетельств, отбор и заморозка продолжаются. При достижении численного лимита новые кандидаты не предлагаются, но запланированные проверки уже предложенных завершаются, если человек не дал команду остановки.

Выбери ровно заданное число различных кандидатов по совокупности доступных свидетельств. Учитывай качество, разнообразие механизмов, устойчивость, риск переобучения и пользу закрытой проверки. Это не механический выбор top-K по score: более низкий балл может сопровождаться полезным отличием метода. Не предписывай фиксированные доли «лучших, средних и худших»; состав определяется задачей и измерениями.

Запиши в `<campaign_dir>/selection.md` основание завершения и его свидетельства, число предложенных решений и оставшихся мест до лимита, состояние проверок, условия сравнения, доступные train/public-оценки, ограничения и причину выбора каждого кандидата. Не смешивай разные наборы и версии условий. При пустом public опирайся на выбранные агентом train-замеры; отсутствие измерения отметь явно. Train-ресурсы содержат токены и время решателя и неизвестный usage, отдельно расходы оценщика. Public раскрывает только общий score, private-данных здесь нет.

Для каждого выбранного кандидата сверь сохранённое ревью по `prompts/reviewer.md` с хешами отправляемого снимка и материалов. Нужны вывод о допустимости, происхождение спорных подсказок и известные риски переобучения. Высокий score не заменяет ревью. Кандидат с нарушением, невыясненной допустимостью или отсутствующим ревью не отправляется. Если таких проверенных кандидатов меньше требуемого числа, сообщи препятствие; не меняй K, не дополняй набор копиями и не расходуй private-допуск. После команды остановки используй только сохранённые свидетельства.

Для каждого финалиста сохрани ID, родителей, неизменяемый снимок и хеш передаваемого пакета, конфигурацию, зависимости и ссылки на свидетельства. Заморозь весь список до первого private-допуска. Упакуй его командой `python -m evaluator.client pack` по README, затем выполни `python -m evaluator.search --journal <абсолютный путь к журналу> finalize --bundle <finalists.json>` по `common/search-history.md` и только после успешной фиксации отправляй пакет через `evaluator.client submit`. Ошибка финализации означает незавершённую подготовку отправки; её нельзя обходить прямым submit. Финализация закрывает новые предложения и проверки и связывает журнал с конкретным пакетом. При досрочной остановке настроенный private-сервис дополнительно требует операторское подтверждение исходной команды человека; локальная запись `stop` или `finalize` его не заменяет. Нельзя проверить одного, а затем выбрать или изменить остальных. Новый ID кандидата или кампании не обходит запрет повторного private-допуска.

`finalize` сохраняет предварительный выбор; необратимое принятие выполняет private-сервис после всех проверок допуска. Если пакет отклонён до принятия, исправь упаковку или состав из уже зарегистрированных снимков через `finalize --bundle corrected.json --replace` по `common/search-history.md`. Сохрани причину исправления и обнови `selection.md`; новые предложения и проверки остаются запрещены. При досрочной остановке операторское свидетельство должно соответствовать исправленному пакету. При неизвестном исходе отправки сначала получи статус либо повторно доставь исходный пакет.

Повторная доставка идентичного принятого пакета возвращает прежнее состояние без запуска. После принятия инфраструктурная ошибка не возвращает допуск; API не возобновляет серию и не сбрасывает квоту. Диагностику читает только оператор в закрытом контуре. Не запрашивай private-вопросы, эталоны, ответы, трейсы, промежуточные или итоговые оценки.

Оценщик самостоятельно выполняет всю private-серию и выбирает точное заданное число лучших по направлению метрики, затем по общему правилу токенов и времени решателя. Это правило финального выбора не включает разнообразие. Исследователь получает только статус и после завершения. Результаты и выбранные решения доступны оператору; private закрывается для новых допусков.

Не управляй отдельными запросами и не опрашивай API часто. Рассчитай ожидание по сопоставимому train-прогону и разрешённым сведениям о размере серии либо используй операторский интервал из `common/long-runs.md`. Принятый пакет не нужно отправлять снова ради продолжения.

Исследовательский отчёт содержит замороженный входной набор, основания выбора, доступные train/public-свидетельства, статус отправки и ограничения. Private-результаты в него не копируются. Оператор получает отдельный финальный результат с N решениями и измерениями. Публикация результата не означает развёртывания в продукте.
