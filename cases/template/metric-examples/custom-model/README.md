# Собственное судейство

Этот пример совмещает программную проверку и LLM. Пустой ответ получает 0 без обращения к модели; непустой оценивается по правилам `policy.json`. Поле `votes` задаёт любое положительное число независимых запросов с одинаковыми входами; в примере их 2. `judge.py` ожидает JSON с числовым `score` от 0 до 1, проверяет ответ и усредняет оценки. Неисправный ответ вызывает ошибку, а не выдуманный балл. Сам код и формат правил можно заменить любым алгоритмом кейса: ограничение двумя этапами или этой шкалой отсутствует.

`metric.json` объявляет `command.uses_model: true`. Во входном JSON арена передаёт `example`, один ответ решателя `answer`, зафиксированное имя `model`, временный `model_base_url` и `model_request_timeout`. Команда отправляет обращения только по этому URL. Ключ модели не нужен: доверенный gateway применяет зафиксированные настройки, выполняет технические повторы и записывает расходы. Не добавляй автоматические повторы HTTP-клиента поверх повторов gateway и не повторяй корректную оценку ради улучшения балла.

Не сохраняй временный URL в выводе, статистике или логах. `statistics` содержит детали судейства, а доверенный расход токенов арена берёт из gateway отдельно. Общий `timeout_seconds` должен покрывать все последовательные запросы и возможные технические повторы. `policy.json` читается относительно `__file__`; запуск не зависит от рабочей директории.

Из корня репозитория `uv run pytest tests/test_metric_examples.py` проверяет этот пример с локальным подставным HTTP-сервером, без реальной модели. После изменения алгоритма подготовь свои проверки. Используй этот каталог как `--metric` при заморозке или перенеси его содержимое в `cases/<case>/metric/`. Нужные зависимости устанавливает оператор; пример использует только стандартную библиотеку Python. Код метрики исполняется в доверенном окружении оценщика и проходит операторскую проверку до доступа к закрытым данным.
