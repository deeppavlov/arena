# Шаблон кейса

Скопируй этот каталог в `cases/<case_id>`, опиши задачу, желаемую оценку в `metric/` и разрешённые данные. Перед поиском передай кейс [агенту подготовки](../../prompts/prepare.md): он проверит постановку, реализует и проверит метрику, подготовит пакет и инструкции для оператора. После готовности инфраструктуры запускай [поисковый промпт](../../prompts/start.md). Кейс может оценивать программу без LLM, модельное решение или оба варианта.

До первого замера определи:

- задачу, формат входа и ответа, разрешённые материалы;
- допустимые изменения в промпте кампании: код, представление данных, промпты, инструменты либо выбор харнеса и его параметров;
- фиксированную модель и её параметры, если она используется, реестр разрешённых харнесов с версиями образов и фиксированные компоненты решения;
- версии train, public, private и эталонов, размер каждого split, версию метрики, направление `maximize` или `minimize`;
- критерии сопоставимости замеров и обязательный учёт токенов и времени по [общему правилу выбора](../../common/public-evaluation.md);
- лимит предложенных решений и условия итогового отбора; при непустом private — точное число входных финалистов и лучших решений на выходе, выходных не больше входных; при пустом private — размер и правило выбора по доступным свидетельствам;
- таймауты исполнения и способ сохранения долгих заданий по [протоколу ожидания](../../common/long-runs.md).

Лимит относится ко всем предложенным решениям, включая неработающие и неудачные. Такие кандидаты сохраняются вместе с гипотезами, результатами и родителями. Токены и время измеряются, но не служат бюджетом поиска. По команде человека прекращается предложение решений и запуск новых проверок; уже запущенные проверки завершаются, после чего отбор использует накопленные сведения.

Train доступен для замеров, анализа трейсов, обучения и собственных разбиений исследователя. Public скрыт и возвращает только итоговый score кандидата; private не возвращает исследователю ни оценки, ни решения даже после завершения. Любой раздел — train, public или private — может быть пустым. Пустые разделы не оцениваются; отсутствие измерения не заменяется нулём. Исследователь выбирает сравнения по доступным данным; условия выбранных замеров фиксируются, результаты разных наборов не смешиваются в одну кривую.

При непустом private отбор обосновывается качеством, разнообразием, устойчивостью и признаками переобучения. Это точный пакет заданного размера; фиксированного top-5 и универсальной квоты на каждый признак нет. Приватный оценщик выбирает точное число лучших решений по метрике, при равенстве — по ресурсам. При пустом private его сервис и отправка не нужны: кампания завершается зафиксированным выбором по доступным свидетельствам без закрытого ранжирования. Подробности кампании смотри в [протоколе](../../common/research-protocol.md), учёт кандидатов, родословной и кривой/AUC — в [журнале поиска](../../common/search-history.md).

Папка [metric/](metric/README.md) содержит исполняемый программный пример точного сравнения строк. Дополнительно даны [встроенный модельный профиль](metric-examples/llm/README.md) с настраиваемым числом голосов и [собственное смешанное судейство](metric-examples/custom-model/README.md). Выбери подходящую основу и замени правила под задачу до заморозки. Агент подготовки может написать другую команду и агрегацию по [контракту оценки](../../common/public-evaluation.md); программная метрика не требует модели. Подготовленный пакет устанавливается одинаковым для всех используемых разделов, закрытые данные подключает оператор отдельно. Общий `evaluator.train` предоставляет сервис и CLI измерений; для нового кейса настраиваются данные, метрика и runner. Собственный train-адаптер нужен только при несовместимости со штатным контрактом.

Данные для оценщика — UTF-8 JSONL, одна запись на строку:

```json
{"id":"example-001","input":"Задача и доступные входы","reference":"Зафиксированный эталон"}
```

`reference` не передаётся решателю; если метрика не требует эталона, поле можно не задавать. Для файловых задач адаптер преобразует вход и результат в согласованный строковый формат. Разрешённые общие файлы доступны в `/assets`. Закрытые public/private JSONL и материалы хранит оператор вне репозитория и build context.

`ways/example/prompt.md` подходит к модельному режиму комплектного харнеса. Для обычной программы используется `solve.py`, для стороннего харнеса — операторский адаптер по [протоколу запуска](../../common/runner-contract.md). Сценарий из нескольких исследовательских запусков задаётся отдельными кампаниями, без изменения общего протокола арены.
