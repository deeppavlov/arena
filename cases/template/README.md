# Шаблон кейса

Скопируй этот каталог в `cases/<case_id>` и заполни описание задачи, метрику и данные.

До первого замера определи:

- задачу и формат входа/ответа, разрешённые материалы и ограничения;
- что именно кандидат может менять: код, представление данных, промпты, инструменты или их композицию;
- фиксированные модель, параметры, харнес и его образ;
- версии датасета, эталонов и метрики, порядок подготовки и проверки эталона;
- одинаковую публичную выборку для отбора финалистов и обязательный учёт токенов и времени по [общему правилу выбора](../../common/public-evaluation.md);
- лимиты кампании и условия остановки, число финалистов до пяти, таймауты и способ сохранения долгих заданий по [протоколу ожидания](../../common/long-runs.md).

Заполни `metric/metric.json`. Текст `instruction` описывает оцениваемую задачу, а `question` каждого критерия должен включать понятную шкалу 1–5. При необходимости замени критерии шаблона; веса нормируются кодом.

Исследователь вправе делать короткие screening-прогоны по подвыборкам public. Фиксируй ID выбранных примеров до запуска; не выдавай оценку одной подвыборки за результат всего public. Private-подвыборки API не поддерживает.

Данные для кода оценщика — UTF-8 JSONL, одна запись на строку:

```json
{"id":"example-001","input":"Задача и доступные входы","reference":"Зафиксированный синтетический эталон"}
```

`reference` никогда не передаётся решателю. Для файловых задач операторский харнес преобразует вход и результат в согласованный формат; общему оценщику достаточно строкового входа и ответа. Разрешённые общие файлы доступны в `/assets`. Private JSONL и закрытые assets хранит оператор вне репозитория и build context.

Первый простой кандидат есть в `ways/example/prompt.md`. Этот способ подходит к комплектному демонстрационному харнесу. Для существующего харнеса реализуй операторский адаптер по [протоколу](../../common/runner-contract.md).
