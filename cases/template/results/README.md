# Результаты

Записывай train-замеры с составом подвыборки и трейсами, а для public — только полученный от оценщика итоговый score. Сохраняй версии кандидатов, родителей и условий, ссылки на MLflow и основания отбора. Неудачные решения и их место в счётчике попыток сохраняются.

Для train-замеров обязательны `score` либо явная ошибка, `solver_tokens`, `solver_seconds`, `solver_unreported_attempts`; судейские затраты хранятся отдельно с префиксом `judge_`. При наличии попыток без usage расход неполон. У немодельного решения полный учёт нулевых токенов. Public-трейсы, ответы, отдельные оценки и закрытые расходы сюда не попадают.

Для графика эволюции и AUC сохраняй порядок предложения, времена запуска и завершения, родителей, направление метрики и идентификатор сопоставимого набора. Train и public образуют отдельные серии; разные подвыборки не смешиваются. Итог private остаётся в закрытом хранилище оператора, включая выбранные решения и их оценки.
