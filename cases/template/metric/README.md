# Метрика кейса

Опиши здесь, что означает хорошее решение: допустимый формат ответа, шкалу, направление улучшения, необходимость эталона, правила нормализации и агрегации. Передай папку агенту с [промптом подготовки](../../../prompts/prepare.md). Он реализует оценку, проверит её на искусственных примерах и подготовит замороженный пакет до начала поиска.

Этот исполняемый пример — программное точное сравнение строк. `score.py` возвращает 1 при полном совпадении ответа с `reference` и 0 иначе. Пробелы, регистр и Unicode не нормализуются. Отсутствующий эталон является ошибкой. Итог по набору — среднее; `direction` равен `maximize`. Это демонстрация контракта, а не универсальное определение качества: замени её правилами своего кейса до кампании.

Проверка без модели из корня репозитория:

```bash
uv run python cases/template/metric/score.py <<'JSON'
{"example":{"id":"synthetic","input":"Верни число 42","reference":"42"},"answer":"42"}
JSON
uv run pytest tests/test_metric_examples.py
```

После изменения метрики подготовь собственные синтетические проверки: верные и ошибочные ответы, граничные случаи, ошибки входа и агрегацию. Проверки шаблонов проверяют только шаблоны. Убедись, что измеряется нужное качество, а ошибки не превращаются в выдуманный нулевой балл.

Файлы пакета: `metric.json` задаёт исполняемый способ оценки, `score.py` — реализацию. Можно добавлять скрипты, рубрики, конфигурацию и другие открытые ресурсы. Пути внутри `argv` относительны папке пакета; локальные ресурсы из Python читай относительно `__file__`, потому что процесс запускается из `/`. Внешние зависимости устанавливает оператор в закреплённое окружение. Секреты и реальные закрытые данные в пакет не входят.

Заморозка после проверки:

```bash
uv run python -m evaluator.prepare freeze \
  --metric cases/my-case/metric --output runs/my-campaign/metric
uv run python -m evaluator.prepare verify --metric runs/my-campaign/metric
```

`freeze` создаёт новый каталог с `metric.lock.json`, который перечисляет файлы пакета и их executable-биты. `verify` проверяет структуру пакета. Эти команды не запускают судейство и не доказывают качество метрики; подготовительный агент проверяет семантику отдельно. Пакет устанавливается оператором целиком, до запуска поиска; во время кампании его менять нельзя.

Другие отправные точки — [встроенный модельный профиль](../metric-examples/llm/README.md) и [собственная смешанная оценка](../metric-examples/custom-model/README.md). Для них используй соответствующий каталог как `--metric`. Собственная метрика может быть программной, модельной или сочетать оба способа; арена не задаёт ей количество судейских голосов и порядок вычислений. Общий контракт описан в [правилах оценки](../../../common/public-evaluation.md).
