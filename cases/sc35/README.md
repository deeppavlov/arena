# SC-35: проверка ПМИ по ЕСПД и типографике

Кейс проверяет один DOCX программы и методики испытаний по зафиксированным требованиям ЕСПД и редакционным рекомендациям. Решатель возвращает один JSON `sc35-span-review-v1` с категориями замечаний, их местами в каноническом тексте и основаниями. Исправление документа в задачу не входит. Полное задание сохранено в [task.md](task.md). Условия первого запуска находятся в [кампании `sc35-first-20261028`](campaigns/sc35-first-20261028/README.md); фактическая готовность определяется её `preparation.md`.

## Вход и ответ

Вход арены — строка JSON с `case_id`, `docx_base64` и идентификаторами документа и канонического текста по контракту исходного пакета. Решатель получает только текущий документ и разрешённые материалы. Канонический текст извлекается штатной проекцией `sc35-corrupted-text-v1`; интервалы замечаний задаются полуинтервалами `[start,end)` в Unicode code points. Несовместимое повторное извлечение текста меняет координаты и недопустимо.

Окончательный `answer` содержит сериализованный review. Находки сохраняют категорию, span, конкретное замечание и основание. Для требований ГОСТ используется `basis_kind=gost_requirement`, для типографики — `basis_kind=editorial_recommendation` и `severity=recommendation`. Неизвестную геометрию и недоступный контекст нельзя превращать в доказанные нарушения; структурный якорь отмечается явно. Схема ответа находится в [metric/review.schema.json](metric/review.schema.json).

## Данные и метрика

Набор `sc-35-espd-unified-v1`, версия `1.0.0`: 881 вход, 1 067 ожидаемых замечаний и 28 контролей. Train/Public/Private = 113/128/640. Все варианты происходят от одной раскрытой ПМИ: split удерживает повреждения, а не независимые исходные документы. Разметка полна только в установленных правилах и областях; результат не является приёмкой всей ЕСПД. Подробнее — [описание данных](dataset/README.md) и [реестр покрытия](dataset/coverage.json).

Единственная метрика — `sc35-span-unified-v1`, `kind=command`, направление `maximize`: `100 × macro F1` категорий по всем примерам оцениваемого набора вместе. Сначала по каждой категории суммируются символьные статистики пересечений, предсказаний и эталона; затем вычисляется F1 и среднее по активным категориям. Среднее отдельных оценок примеров эту агрегацию не заменяет. Micro precision/recall/F1 и IoU служат диагностикой. Оценщик не обращается к LLM и не проверяет свободную истинность текстового обоснования. Исходный пакет находится в [metric/](metric/); кампания использует отдельную замороженную копию.

## Исходное решение и поиск

[Baseline](ways/baseline/) объединяет граф требований, формальные проверки OOXML, типографику и содержательную LLM. Профиль содержит 99 нормативных и 14 редакционных правил. Содержательный модуль получает 40 правил; `rule_assessments` отделяет выполненные проверки от недоступных условий, а `configuration_candidates` — требующие рендера наблюдения от доказанных `findings`. Наличие обработчика в реестре не означает, что каждое правило полностью проверено на каждом документе. Предложенные направления исследования собраны в [proposal](prompts/proposal.md).

На GPU6 внешний исследователь и агентский решатель используют Hermes; готовый baseline подключён отдельным `sc35-content` через тот же внутренний gateway. Контракты и зависимости описаны в [harness/README.md](harness/README.md). Разрешённые изменения, модель, лимит предложений и отбор определяет только выбранная кампания.

В Git и образах находятся код, общие правила и разрешённые метаданные. Реальные DOCX, JSONL и эталоны остаются вне Git. Исследователь получает открытый train, общий public-score и только статус private; закрытые генераторы, полный манифест, происхождение повреждений, эталоны public/private и закрытые трейсы в его workspace не передаются.

## Проверки и запуск

Проверки кейса выполняются на синтетических данных без реальных модельных вызовов:

```bash
uv run --with lxml==6.1.3 --with jsonschema==4.26.0 pytest cases/sc35/tests
```

Общие обязательные проверки перечислены в [RPD.md](../../RPD.md). Сборка образов, приёмка на GPU6, проверка private-защиты и MLflow записываются в [preparation.md](campaigns/sc35-first-20261028/preparation.md). Поиск запускается отдельной командой пользователя по [start.md](campaigns/sc35-first-20261028/start.md) после завершения подготовки.
