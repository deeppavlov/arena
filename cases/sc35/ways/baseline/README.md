# Исходный baseline SC-35

Переносимый метод `espd-format-typography-content-v3` из пользовательского пакета. `solution.json` выбирает зарегистрированный оператором харнес `sc35-content`; модель и gateway задаются доверенной инфраструктурой. Этот каталог является исходным предложением: подготовка не регистрирует его в журнале поиска и не измеряет качество на реальных документах.

`solve.py` проверяет входной JSON, восстанавливает DOCX во временный каталог и запускает граф, формальные проверки, типографику и содержательный модуль с 40 правилами. Результат — одна строка JSON `sc35-span-review-v1`. Подставной клиент в синтетических тестах проверяет контракт; исходный исторический детерминированный Train-score 34,41/100 не является модельным результатом этого запуска.

`assets/profile.json` и `assets/taxonomy.json` фиксируют открытые требования и категории. В `runtime` отсутствуют реальные документы и эталоны, инвентарь исходного GOLD и генератор датасета. Внутренний модуль `span/build_dataset.py` содержит только совместимую функцию сохранения JSON. Неиспользуемая DOCX-методом PDF-ветка графа импортирует `pypdf` лишь при отдельном обращении к PDF; базовому методу достаточно `lxml` и `jsonschema` из образа.

Метод не добавляет повторов поверх gateway и не повторяет валидный ответ ради score. Подготовительные действия, модельные вызовы, инструменты и технические повторы учитываются как ресурсы решателя по общему контракту Arena. Изменения метода и проверки качества выполняются только в отдельном поисковом запуске.
