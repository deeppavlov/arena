# Метрика SC-35

Единственная оценка — детерминированное пересечение интервалов Unicode code point по категориям. `metric.json` использует `kind: command`, направление `maximize`, версию `sc35-span-unified-v1` и `uses_model: false` у оценки примера и агрегатора. LLM-судьи нет.

`score.py` принимает пример и строку ответа, проверяет схему `sc35-span-review-v1`, идентичность документа, текста и таксономии и возвращает символьную статистику. `aggregate.py` суммирует её по категориям всего выбранного split; итог — `100 × macro F1` активных категорий. Это не среднее F1 отдельных документов. Пустой набор, дубликаты ID, неверная схема или интервалы завершаются ошибкой, а не нулевой оценкой.

Оценивание ограничено зафиксированными правилами и областями эталона. Находки вне подтверждённого покрытия не доказывают ни качество, ни ошибочность решения; категория и место не подтверждают истинность свободного текста обоснования. Пересекающий область слишком широкий интервал учитывается целиком. Редакционные рекомендации и обязательные требования ГОСТ сохраняют разные основания.

Программная метрика не обращается к модели. Arena измеряет её время отдельно от времени и токенов решателя. Требуемые зависимости: `lxml==6.1.3`, `jsonschema==4.26.0`. Формула и правила сопоставления перенесены из исходного пакета без изменения.

Синтетические проверки выполняются без реальных документов, закрытых эталонов и модели:

```bash
uv run --with lxml==6.1.3 --with jsonschema==4.26.0 python -B -m unittest discover -s cases/sc35/tests -v
```

Проверки включают запуск дочерних команд через `evaluator.metrics`, корпусную агрегацию, ошибки интервалов, пустые и повторные результаты, идентичность входа, переносимость baseline и подставной содержательный ответ. Рабочий пакет замораживается в явно выбранной кампании через `evaluator.prepare`; этот исходный каталог не является свидетельством готовности сервисов.
