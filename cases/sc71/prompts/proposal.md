# Пропозал поиска SC-71

Этот документ — начальная карта гипотез для исследовательского Hermes. Читай его вместе с [условиями кампании](../campaigns/sc71-first-20261019/campaign.md), общими правилами и исходниками `cases/sc71/proposals`. Он не является нормативным источником для ответа на вопрос и не подаётся решателю как текст KB.

## Предложения пользователя

Пользователь предложил проверить, какое представление исходной Markdown-базы лучше помогает отвечать. Для RAG можно создать SQLite-базу BM25, другой индекс или комбинированный поиск. Создание любого такого представления относится к методу поиска и учитывается в решении; оно не выполняется бесплатно на этапе подготовки арены.

Файловому Hermes может хватить плоской Markdown-базы в её нынешнем виде. Альтернатива — дерево папок, похожее на исходную структуру документов. Можно сделать собственную более полезную иерархию, прибраться в документах, создать новые тематические разделы. Ещё одна гипотеза — README в каждой папке и подпапке, которые помогают навигации. Возможен и простой поиск через grep без индекса. Польза структуры, очистки, README и индекса заранее неизвестна: её должна установить арена.

Реорганизация или переписывание представления разрешены, но не меняют доказательства: сохраняй исходный Markdown, стабильный `origin_id`, координаты или другую проверяемую привязку. Производные README, планы и пересказы не заменяют дословную цитату исходного документа. Удаление OCR-ошибки из поискового представления не разрешает исправить её в цитате.

Для всех агентских способов используется закреплённый Hermes. Методы RAG, которые выдают только ранжированный список, подключаются к нему инструментом. Модель должна получить явное обязательное указание вызвать этот инструмент, а проверка — подтверждение реального вызова. Файловый агент получает разрешённую файловую систему в выбранном виде и самостоятельно ищет по ней. Можно исследовать сочетания этих подходов.

Исследователь может искать дополнительные идеи в интернете и предлагать собственные. Внешние поисковые запросы касаются только общедоступной методологии; вопросы, эталоны, документы KB и их фрагменты туда не отправляются. Сам решатель отвечает по разрешённой KB и получает только внутренний модельный доступ.

Разрешены локальные embedding- и reranker-модели. Сначала проверь требования к CPU/GPU, памяти, диску, зависимости и доступные ресурсы GPU6, затем скачивай и запускай подходящую модель. Фиксируй версию весов и конфигурацию внутри версии решения. Все генеративные обращения — исследователь, решатель, планировщик, вспомогательные агенты, сжатие и судья — используют только внутреннюю `deepseek-ai/DeepSeek-V4-Flash-0731` с `reasoning_effort=max`.

## Семь исходных направлений

Исходники `cases/sc71/proposals` дают проверяемые механизмы. Они могут быть переработаны, объединены, заменены или опровергнуты в пределах лимита предложенных решений кампании.

| Направление | Гипотеза | Проверка, способная её опровергнуть |
| --- | --- | --- |
| `bm25_sections` | Обычная нарезка и BM25 находят точные термины и реквизиты | Не найдены нужные основания при известных формулировках; пропуски при перефразировании |
| `structure_bm25` | Заголовки, целый пункт и соседнее окружение сохраняют условия и исключения | Шум вытесняет доказательства, при сопоставимых условиях ответ не улучшается |
| `amendment_bm25` | Пара «основание изменения + исходная норма» помогает выбрать редакцию | Связи ошибочны или не добавляют нужного основания |
| `planned_bm25` | Декомпозиция вопроса и объединение выдач покрывают несколько оснований | План искажает реквизиты, увеличивает шум и не улучшает ответ |
| `file_agent` | Последовательное чтение по наблюдениям помогает пройти цепочки отсылок | Агент выбирает неверные ветки и тратит больше ресурсов без выигрыша |
| `hybrid_bge` | Dense-поиск дополняет BM25 при перефразировании | Смысловая ветка не добавляет нужных мест или вытесняет точные совпадения |
| `linked_hybrid` | Явные ссылки ведут к недостающим документам | Разрешённых связей нет или расширение не добавляет доказательств |

В исходном пакете `file_agent` — небольшой JSON-контроллер поверх структурного поиска. Для этой кампании агентский способ переносится в Hermes; четыре хода, `effort=low` и старый timeout 600 секунд не являются условиями кампании. Аналогично прежний планировщик должен использовать общую фиксированную модель и `max`.

Указанные в исторической методологии готовые SQLite-индексы и векторы не являются подготовленными assets этой кампании. Их наличие не освобождает кандидат от создания, версионирования и учёта своего представления. Прежняя сборка `linked_hybrid` имела ноль разрешённых связей; её результаты не подтверждают пользу графового расширения.

Старый адаптер `prepare.py → context → одношаговый ответ` не выполняет требование обязательного Hermes-инструмента автоматически. Для выбранного варианта реализуй совместимый инструмент либо файловый доступ и проверку исполнения, сохранив единый runner-контракт. Исторические рекомендации о фиксированном промпте ответа, обязательном запуске всех семи вариантов, готовых индексах, CPU-only и отдельных параметрах уступают явно зафиксированным условиям этой кампании.

## Как получать свидетельства

До реализации запиши механизм, ожидаемый эффект, опровергающую проверку и родителей в claim; зарегистрируй версию в общем журнале до её проверки. Каждый вариант, включая абляцию и неработающий метод, занимает одно место из 100. Технический повтор неизменённого запроса новым решением не является.

Сравнивай полезность конечного ответа по основной метрике. Recall и покрытие исходных оснований помогают объяснить результат только на доступном train. Для компонентных выводов удерживай остальные факторы одинаковыми; при смене нескольких стадий называй результат сравнением систем. Не считай семь названий семью различными механизмами без проверки реализации.

Сохраняй стоимость построения представления, модельные вызовы, время, токены, размер и ресурсные требования. Для общей подготовки зарегистрируй неизменяемый `build.py` и выполни его через `evaluator.build` по [инструкции](../tools/assets.md); сервис измерит работу без вопросов и эталонов, сохранит квитанцию и предоставит результат в `/assets/prepared`. На каждой целой оценке кандидата добавляются собственные расходы сборки и уникальные квитанции зависимостей ровно один раз. Подготовка отдельного вопроса через `prepare.py` учитывается в этом примере. Неизвестный расход не равен нулю.

Для повторного использования измеренного индекса укажи его digest в `parameters.asset_digests` и включи собственный `build.py`; для простого повторного использования достаточно пустой сборки без копирования индекса. Сервис учтёт исходную подготовку транзитивно и не посчитает одну квитанцию дважды. Обычный publisher предназначен для весов, зависимостей и исходных материалов; он не разрешает обход измерения построения KB.

Train содержит только 10 вопросов, поэтому единичный выигрыш легко переоценить. Используй независимые объяснения ошибок, абляции и устойчивость, когда они возможны; public даёт только общий score. Отбирай 10 различных полезных финалистов по накопленным свидетельствам. Private не служит обратной связью: серия выполняется один раз, 3 итоговых решения и её результаты получает только оператор.
