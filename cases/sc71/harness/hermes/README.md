# Hermes для SC-71

Образ фиксирует upstream `NousResearch/hermes-agent` на коммите `86fa9e6ca1de7ee71132d2be0103f3e37d1fa872`. Нужен Python 3.14: зависимости этой версии Hermes не устанавливаются полноценно на Python 3.12. Зависимости Hermes устанавливаются из его `uv.lock`; extra `ddgs` даёт исследователю поиск в интернете без отдельного ключа. Версия итогового Docker image фиксируется оператором перед кампанией. Для медленной сети можно передать [кеш исходников](source-cache/README.md); версия остаётся той же.

```bash
docker build -f cases/sc71/harness/hermes/Dockerfile -t arena-hermes:sc71 .
docker image inspect arena-hermes:sc71 --format '{{.Id}}'
```

`main.py` реализует [контракт runner](../../../../common/runner-contract.md). Стандартный вход содержит JSON задания, стандартный выход — единственный `{"answer":"..."}`. Модель строго `deepseek-ai/DeepSeek-V4-Flash-0731`, `reasoning_effort=max`. Промежуточные токены, вызовы инструментов, подготовка и субагенты проходят через gateway того же запуска. Gateway остаётся источником учёта токенов и трейсов, доверенный внешний runner измеряет полное время. Локальные сообщения Hermes не попадают в stdout и stderr контейнера; debug-dump запросов выключен.

## Формат кандидата

```json
{"harness":"hermes","parameters":{"mode":"retrieval"}}
```

`mode` принимает `files` (по умолчанию) или `retrieval`. `/candidate/prompt.md` задаёт стратегию и формат ответа. Можно выбрать другой относительный `parameters.prompt_file`. Необязательные `parameters.toolsets` содержат только `terminal`, `file`, `delegation`, `todo`; по умолчанию доступны первые три. `parameters.max_iterations` — целое от 1 до 10000, по умолчанию 10000. Остальные параметры передаются коду метода и не меняют фиксированную модель, endpoint, образ, mounts или настройки делегирования.

Сырые разрешённые материалы доступны в `/assets`, код метода — в `/candidate`, рабочие файлы — в `/tmp/arena-workspace`. Все эти пути явно сообщаются решателю. Для SC-71 образ содержит ссылку `/kb` на `/assets/kb`, поэтому исходные адреса цитат `/kb/norm/...md` разрешаются без изменения KB. Файловый метод использует инструменты Hermes прямо на файлах. По умолчанию ему доступна исходная плоская KB; копирование, создание дерева, README, SQLite, embeddings или другого представления выполняет сам метод. Эти действия входят во время решения; индексы при подготовке арены не создаются.

Необязательный `prepare.py` запускается до Hermes в рабочем каталоге метода. Он получает через stdin:

```json
{"input":"вопрос","parameters":{},"assets_dir":"/assets","candidate_dir":"/candidate","workspace_dir":"/tmp/arena-workspace","model":"deepseek-ai/DeepSeek-V4-Flash-0731","model_base_url":"выданный gateway URL","model_request_timeout":130410}
```

Он возвращает JSON-объект с необязательным `context` типа string. Доступ к модели из кода метода осуществляется через выданный gateway URL; его нельзя записывать в файлы, ошибки, трейсы или переменные окружения. URL содержит временный секрет допуска. Подготовка ограничена операторским таймаутом 48 часов, весь пример — 7 сутками.

В режиме `retrieval` обязателен `retrieve.py`. Он получает такой же объект и дополнительно `arguments: {"query":"поисковый запрос"}`; возвращает JSON-объект, например `{"results":[{"text":"цитата","source":"документ"}]}`. Runner регистрирует его как инструмент `arena_search`, прямо требует `MUST call arena_search before producing the final answer` и отклоняет ответ, если инструмент ни разу успешно не был вызван. Ранжированный список поступает модели как результат инструмента, окончательный ответ генерирует Hermes. Внутренний поиск через grep не заменяет обязательного вызова RAG-tool.

Дополнительные инструменты определяются в `tools.json`:

```json
[{"name":"arena_outline","description":"Read a document outline","parameters":{"type":"object","properties":{"document":{"type":"string"}},"required":["document"]},"script":"outline.py"}]
```

Скрипт получает тот же контекст и объект `arguments`. Имя инструмента, описание, JSON Schema и скрипт входят в неизменяемый пакет кандидата. Скрипты выполняются тем же Python, могут импортировать соседние файлы кандидата и должны возвращать один JSON-объект не более 1 MiB. Реестр инструментов доступен субагентам Hermes; кандидат может задавать им инструменты через обычные параметры делегирования.

## Общий профиль

`config.yaml` один для исследователя и решателей:

- `max_concurrent_children=30`, `oneshot_max_children=30`, `max_spawn_depth=3`;
- до 10000 шагов основного агента и каждого дочернего агента;
- 130410 секунд ожидания gateway, покрывающих шесть попыток по 6 часов и паузы;
- семь суток для терминальных команд, общего исполнения инструментов, жизни терминала, heartbeat дочерних агентов и проверки зависших фоновых делегирований;
- выключены короткий watchdog хода, общий временной бюджет Hermes и fallback-модели;
- интерактивные подтверждения команд выключены внутри ограниченного контейнера;
- все вспомогательные генеративные функции используют ту же внутреннюю модель с `max`.

Upstream ограничивает ширину одного пакета делегирования, а one-shot cap — суммарное число детей одного родителя. Эти настройки **не означают общий предел 30 одновременно работающих агентов во всём дереве**. Оператор фиксирует CPU, RAM, PID и размер scratch для контейнера; внешний процесс ограничивает жизнь одного решателя семью сутками. Глубина 3 допускает корень, детей, внуков и правнуков; возможность дальнейшего делегирования определяется глубиной агента. Устаревший аргумент `role` закреплённая версия Hermes не использует.

OpenAI SDK имеет ноль повторов; Hermes — одну попытку, без auto-recovery. При ошибке gateway адаптер запрещает дальнейшие модельные обращения в этом процессе и возвращает явный сбой. Поэтому скрытая логика восстановления Hermes не повторяет уже исчерпавший пять повторов запрос. Успешные ответы ради качества не перезапрашиваются. Gateway проверяет ответ и usage до возврата в Hermes. SDK-параметры нормализуются до разрешённого протокола; полезные messages/tools из специального `extra_body` Hermes сохраняются.

## Исследователь

Контейнер исследователя имеет разрешённую рабочую копию в `/workspace`, доступ к интернету через операторский proxy, train и submit API. Он не получает Docker socket, операторский SSH, public/private данные или их трейсы. Выход в интернет предназначен для общих идей; данные кейса и KB внешним сервисам не отправляются. Решатели используют изолированную сеть с внутренним gateway и интернет-инструментов не получают.

Оператор передаёт файл `ARENA_MODEL_ACCESS_FILE` (по умолчанию `/run/arena/model-access.json`) с `model`, `model_base_url` и `model_request_timeout`. Вместо последнего допускается `model_timeout` одной upstream-попытки; адаптер рассчитывает полное ожидание gateway. `api_key` необязателен и нужен только при отдельной авторизации gateway. Содержимое читается в память; реальные реквизиты не копируются в конфигурацию Hermes или окружение.

По отдельной команде пользователя оператор запускает:

```bash
python /opt/arena/cases/sc71/harness/hermes/researcher.py \
  --prompt-file /workspace/cases/sc71/campaigns/sc71-first-20261019/start.md \
  --journal /workspace/cases/sc71/campaigns/sc71-first-20261019/search.sqlite3 \
  --private-url http://private-evaluator:8080 \
  --private-finalists "$SC71_FINALISTS" --private-release-id "$SC71_PRIVATE_RELEASE_ID" \
  --private-token-file /run/arena/private-token --cwd /workspace
```

`--prompt-file` можно задать через `ARENA_RESEARCH_PROMPT_FILE`. `HERMES_HOME` задаёт каталог профиля; по умолчанию `/workspace/.hermes`. Launcher сохраняет туда только общий профиль без секретов. Сам launcher не запускает подготовку и не обходит проверку готовности из стартового промпта. Подготовка этого образа не начинает исследовательскую кампанию.

Путь к единому журналу, адрес status-only private API, ожидаемые число финалистов `--private-finalists` и `--private-release-id` задаются явно. Оба значения берутся из зафиксированной операторской конфигурации кампании; при развёртывании GPU6 это `SC71_FINALISTS` и `SC71_PRIVATE_RELEASE_ID` из `operator/images.env`. Перед созданием агента launcher проверяет `/v1/search-readiness`: сервер работает в режиме кампании, защита private включена, журнал читается и серверный лимит совпадает с локальным, а число финалистов и release ID — с переданными значениями. Недоступный endpoint или несовпадение останавливают запуск без модельного хода, в том числе при повторном входе. Успешное завершение одного `run_conversation` означает окончание хода Hermes, а не кампании. Launcher сверяет журнал и private-статус; если работа остаётся, он продолжает тот же экземпляр агента с возвращённой историей разговора. При исчерпанном лимите разрешены только проверки зарегистрированных решений и финализация; после записи остановки — ожидание уже начатых проверок и отбор. При активных проверках launcher возвращает агенту управление вместе с их ID: сервис сам не завершает записи журнала, поэтому агент получает train-результат через `evaluator.train result`, а public-результат фиксирует через `evaluator.search finish`. Если задание ещё выполняется, агент блокирующе ждёт рассчитанный срок средствами инструментов по `common/long-runs.md` и затем собирает результат в том же ходе. Два завершённых хода без изменений журнала дают явный `incomplete`, чтобы инфраструктурный тупик не запускал бесконечные модельные продолжения.

Успех требует пустой очереди выполняющихся проверок, исчерпанного лимита либо остановки, зафиксированного пакета финалистов и private-статуса `complete`. Право досрочной остановки проверяет доверенный private-сервис. Существующая private-попытка запрещает новый запуск агента. При корректной финализации launcher сам ожидает private-статус: только GET раз в минуту, без новых модельных ходов или отправок. Это действует и при повторном входе в launcher; уже завершённая серия подтверждается без модели. Неожиданная ранняя private-попытка, статус `failed` или сбой API дают ненулевой код и JSON с причиной `incomplete` в stderr. Отсутствие private-попытки подтверждает только HTTP 404 с точным JSON `{"detail":{"code":"no_evaluation"}}`; маршрутный 404, неверный URL и старый API без этого контракта запрещают запуск агента. Он не читает private-результаты, не повторяет модельные ошибки и не открывает новую попытку. Эти изменения предназначены для следующего развёртывания; они не возобновляют использованную private-серию первой кампании.

## Проверка без реальных моделей

```bash
python -m cases.sc71.harness.hermes.mock_check
```

Проверка использует настоящий закреплённый Hermes и локальный подставной HTTP-сервер. Она проверяет пять сценариев: retrieval-tool, чтение файла, делегирование, вложенное делегирование с поиском у внука и отказ gateway. Проверяются реальные сообщения и результаты инструментов, сохранение `reasoning_content`, параметры каждой модельной роли, отсутствие повторного запроса после HTTP 500 и отсутствие тестового секрета в файлах Hermes. Модельные сервисы, настоящий датасет и реальные private-допуски не нужны. Временные каталоги удаляются; stdout содержит один JSON-отчёт.

## Доверенная сборка представления KB

Оператор явно включает `supports_build` и `supports_asset_selection` для этого харнеса. Build-запуск задаёт верхнеуровневое поле `operation: "build"` и отдельный writable mount `/output`. По умолчанию операция — `solve`; другие значения отклоняются. Параметры кандидата не переключают операцию. Адаптер запускает только `/candidate/build.py`, без финального ответа Hermes. Скрипт получает `assets_dir`, `candidate_dir`, `workspace_dir`, `build_dir`, полный объект `parameters` и тот же модельный gateway. Поля `input` в его stdin нет; вопросы и эталоны при сборке не передаются. Задание сборки с полем `input` отклоняется до исполнения. Таймаут — `prepare_timeout`, обычно 48 часов. Скрипт пишет результат в `/output` и возвращает JSON-объект; метаданные этого объекта не являются доказательством затрат.

При успешном завершении runner возвращает `{"answer":"build complete"}`. Доверенный внешний процесс измеряет время, gateway — токены и повторы. Оператор публикует неизменяемый результат с квитанцией затрат, связанной с идентификаторами кандидата и зависимостей. Квитанция учитывается один раз в каждой самостоятельной оценке кандидата. Операцию выбирает доверенный build-сервис; `solution.json` задаёт только параметры метода. Этот режим предоставляет механизм для будущего поиска; подготовка арены не строит представление реальной KB.
