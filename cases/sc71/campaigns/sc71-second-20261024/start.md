# Отдельный запуск поиска SC-71

Выполни `prompts/start.md` для кейса `cases/sc71` и кампании `cases/sc71/campaigns/sc71-second-20261024`, затем работай по `prompts/orchestrator.md`. Этот файл применяется только по отдельной команде пользователя после завершения подготовки. Самостоятельно Git-коммиты не создавай.

До предложений и модельных проверок прочитай `RPD.md`, `README.md`, `AGENTS.md`, `campaign.md`, `preparation.md`, описание кейса, данных и замороженный пакет метрики этой кампании. Выполни все проверки готовности из общего стартового промпта. При любом существенном пробеле перечисли его и заверши запуск, не выполняя подготовку и не меняя установку.

Перед первым ходом и каждым возобновлением получи авторизованный `GET /v1/search-readiness` по private URL из `preparation.md`. Проверь `mode=campaign`, `gate_enabled=true`, `journal_ready=true`, `evaluation_enabled=true`, `max_solutions=100`, `finalists=10`, `output_count=3` и `release_id=sc71-second-20261024`; сохрани дату и ответ без токена. Прочитай указанный в отчёте синтетический train-трейс через исследовательский MLflow, включая входы и выходы вызовов. Старые свидетельства, доступность `/healthz` и наличие run без payload не заменяют эти проверки.

Единый журнал относится только к `sc71-second-20261024`: `/workspace/cases/sc71/campaigns/sc71-second-20261024/search.sqlite3`; общая папка кампании — `/workspace/cases/sc71/campaigns/sc71-second-20261024`. Эти пути одинаковы для всех работников; разрешённые пути train/KB и физическое размещение журнала подтверждает `preparation.md`. Перед первым поиском ожидаются `max_solutions=100`, `proposed=0`, `remaining_proposals=100`; при возобновлении восстанови фактическое состояние и не обнуляй журнал. Не создавай копии журнала и состояния в каталогах работников. Если отчёт не фиксирует эти пути, подготовка не завершена.

Организуй независимые направления через субагентов в отдельных изолированных копиях разрешённых исходников, задавай цель, область записи, исходную версию, доступные данные, общий журнал, условия и места бюджета. Подготовленный `/workspace` очищен от `.git`, истории, архива и других кампаний; начальный коммит для создания worktree не нужен и запрещён. Самостоятельно не создавай Git-коммиты ни в основном каталоге, ни у работников. Если Git-база уже существует в другом разрешённом окружении, отдельные worktree допустимы без новых коммитов. Изолированные копии не содержат отдельных журналов или копий состояния кампании; train и KB используются по общим абсолютным путям из `preparation.md`. Во всех генеративных ролях используй `deepseek-ai/DeepSeek-V4-Flash-0731`, `reasoning_effort=max` и закреплённый Hermes. Профиль внешнего и внутреннего Hermes одинаков: `max_concurrent_children=30`, `oneshot_max_children=30`, `max_spawn_depth=3`. Это ограничения делегирования одного родителя и глубины, а не глобальный предел всего дерева.

Условия поиска: старая Paddle KB, неизменённые эталоны и прежнее разбиение с seed `sc71-first-20261019`; train/public/private — 10/30/60, по 2/6/12 каждой темы. Бюджет — 100 предложенных решений, включая неудачные версии. На private выбираются ровно 10 различных финалистов, оценщик возвращает оператору ровно 3 результата. Токены и время измеряются, но не ограничивают поиск.

Прочитай `cases/sc71/prompts/proposal.md`, `cases/sc71/proposals/README.md` и `cases/sc71/proposals/original/METHODOLOGY.md` как источники гипотез. Условия текущей кампании имеют приоритет над историческими рекомендациями. Старые результаты не являются оценками новой кампании. Интернет разрешён для общих методических идей без передачи заданий, эталонов или содержимого KB внешним сервисам.

Любое представление KB создаётся как часть кандидата после регистрации его неизменяемого снимка. Для RAG подключай выдачу инструментом Hermes, явно требуй его вызова и проверяй фактическое использование. Для файлового метода предоставляй нужное представление файловой системы. Сохраняй привязку к исходным документам; окончательные цитаты берутся из неизменённого источника.

Общую обработку KB выполняй по `cases/sc71/tools/assets.md`: зарегистрируй `build.py`, отправь его доверенному build-сервису, дождись квитанции `FINISHED`. Результат доступен readonly в `/assets/prepared`; стоимость собственной подготовки и уникальных зависимостей учитывается один раз в каждой целой оценке. Для повторного использования измеренного asset нужна собственная сборка. Обычный publisher не заменяет измерение преобразований KB.

Train открыт для анализа и валидации; фиксируй точные составы подвыборок и происхождение сведений из train по `common/research-protocol.md`. Public раскрывает только общий score; private — только статус. Не открывай операторские каталоги, полный датасет, закрытые трейсы, private-оценки и операторский MLflow. Разрешённое зеркало содержит train-трейсы и безопасный общий public-score.

До проверки регистрируй каждую версию и её родителей; используй точный сохранённый снимок. Сохраняй гипотезы, отрицательные результаты, отдельные ресурсы решателя/оценщика, историю, кривую и AUC. Не повторяй валидный ответ ради балла или отсутствующего usage. Следуй длинным таймаутам и порядку ожидания из `common/long-runs.md`; прогоны должны переживать отключение чата.

Продолжай до исчерпания 100 предложений либо явной команды человека остановить поиск. При исчерпании лимита новые решения не предлагаются, запланированные проверки зарегистрированных продолжаются. При команде остановки не начинай новые проверки и не запускай ожидающие, дождись только выполняющихся. Ревью претендентов планируй в ходе поиска. При инфраструктурной блокировке сохрани незавершённое состояние без private-отправки.

Выбери ровно 10 прошедших ревью разных финалистов по качеству, разнообразию, устойчивости и риску переобучения. Запиши причины выбора и выполни `prompts/finalists.md`. Private принимает один замороженный пакет только после проверки допуска. Новая отдельная серия на прежнем split проводится по явной команде пользователя от 24.10.2026; старое private-состояние не сбрасывается. Это повторно используемый контрольный набор. Решение о последующей серии принимает человек; агент не начинает её самостоятельно посредством переименования или сброса истории. Результаты private исследователь не получает.
