# Gateway: подготовка SC-71

## Проверенные свойства

Gateway поддерживает OpenAI function tools, `tool_choice`, сообщения assistant/tool, `tool_call_id`, `tool_calls` и `reasoning_content`. Для ответа с инструментами допускается пустой или отсутствующий текст; для окончательного ответа нужен непустой текст. Неизвестные служебные поля upstream удаляются, включая вложенные поля вызова инструмента. Потоковый режим не поддерживается; `stream: false` допустим.

Модель остаётся операторской. Клиент может повторить зафиксированные параметры только при точном совпадении их JSON-значений; произвольные параметры и изменение значения отвергаются. Hermes может передавать `reasoning_effort: max`, когда то же значение закреплено в `MODEL_PARAMETERS_JSON`. Для DeepSeek в Hermes требуется сохранение reasoning между шагами: `model.reasoning_echo: true`.

## Структурированные ответы судьи

Внутреннее поле запроса `response_schema` проверяет JSON окончательного ответа внутри существующего цикла повторов. Поле не передаётся LiteLLM. Разрешены исключительно схемы из операторского `MODEL_RESPONSE_SCHEMAS_JSON`, по умолчанию список пуст. Сопоставление использует точную каноническую JSON-запись. Для SC-71 в список нужно включить зафиксированную схему голоса из пакета метрики.

Схема не может быть произвольным фильтром качества со стороны кандидата: изменение минимального балла или `const` относительно разрешённой схемы даёт HTTP 400 до обращения к модели. Полный список поддерживаемых ключей, ограничения размеров и глубины описаны исполнимым контрактом `evaluator/response_schema.py`. Ссылки на внешние схемы запрещены. Целый балл не допускает bool или float. Некорректные JSON, повторяющиеся ключи и NaN/Infinity отвергаются.

При технической ошибке остаются первая попытка и пять повторов с прежним запросом. Все попытки учитываются. Корректный низкий балл возвращается сразу. Вложенный цикл повторов в программе метрики не нужен.

## Трейсы

Операторский `MODEL_TRACE_DIR` требует `MODEL_USAGE_DIR`. Каждая модельная попытка сохраняется в отдельном закрытом файле внутри каталога UUID запуска. Чтение: `evaluator.trace_store.read_calls(directory, run_id)`. HTTP API для чтения трейсов отсутствует.

Запись содержит `name`, `span_type`, `inputs`, `outputs`, `attributes`, `status`, `start_time_ns`, `end_time_ns`. Атрибуты содержат модель, номер попытки, usage и необязательные `caller_metadata`. Поле запроса `trace_metadata` предназначено для контекста критерия/голоса, удаляется перед upstream и не определяет права или принадлежность расходов.

Трейсы содержат очищенные сообщения и вызовы инструментов. Заголовки авторизации, upstream URL и исходные тексты транспортных ошибок не сохраняются. API-ключ и текущий capability передаются механизму редактирования как известные секреты. Невалидный JSON внутри корректного chat-ответа сохраняется для диагностики с `status: ERROR`. Ошибка записи трейса приводит к явному HTTP 503; usage попытки сохраняется до записи трейса.

## Проверки

Проверки используют только синтетические запросы и подставной transport. Настоящие модели, реальные примеры и удалённые сервисы в этой работе не использовались. Проверены полный цикл инструмента, reasoning, одинаковые запросы повторов, учёт инструментальных вызовов, границы конфигурации, структурированные голоса, отказ при недоступном хранилище трейсов и удаление секретов. Независимое ревью не оставило блокеров.

GPU6, действующая версия Hermes и LiteLLM требуют общей синтетической приёмки подготовки; модульные проверки её не заменяют.
