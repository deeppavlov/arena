# Синтетическая приёмка SC-71

Сохранённые результаты первой приёмки относятся к прежним исходникам и образам в [свидетельствах кампании](../../../archive/cases/sc71/campaigns/sc71-first-20261019/evidence/README.md) и не подтверждают новую установку. Проверять старые state следует исходным пакетом на GPU6. Для назначенной пользователем кампании `sc71-second-20261024` объём нового технического эксперимента сохранён в [условиях](../campaigns/sc71-second-20261024/campaign.md): одна конфигурация, три синтетических задания. Фактические версии и результаты новой приёмки фиксируются в [отчёте подготовки](../campaigns/sc71-second-20261024/preparation.md), окружение — в [развёртывании](../campaigns/sc71-second-20261024/deploy/README.md); здесь готовность не заявляется.

Приёмка выполняется в согласованном пользователем объёме: одна конфигурация решения, три сценария, без реального датасета, регистрации поисковых кандидатов и допуска private. Все материалы здесь вымышлены. Код сценариев и конфигурацию фиксируют до первого модельного обращения.

1. Hermes обязан вызвать `arena_search` и вернуть точный код `КОД-СЕВЕР-731` из единственного синтетического документа.
2. Тот же кандидат обязан вызвать поиск и создать цепочку родитель → ребёнок → внук. Проверка требует два завершённых `delegate_task`, фактическую вложенность потомков и завершённый `arena_search` у внука в доверенных gateway-трейсах. Связь проверяется через точные goal, начинающиеся с `SC71_ACCEPT_CHILD` / `SC71_ACCEPT_GRANDCHILD`: переданная родителем задача должна стать первым пользовательским сообщением соответствующего потомка. Два вызова одного корневого агента проверку не проходят.
3. Замороженная SC-71 метрика оценивает заранее сохранённый правильный синтетический ответ: девять валидных голосов, по три на полноту, точность и обоснованность, веса 0.35/0.35/0.30. Минимальный приёмочный score заранее задан как 4 из 5. Низкий валидный score сохраняется без повторного судейства.

Доверенные трейсы подтверждают модель `deepseek-ai/DeepSeek-V4-Flash-0731`, `reasoning_effort=max`, вызовы инструментов и отдельный расход решателя/судьи. Число попыток и сумма известных токенов сверяются с отдельным usage-журналом. При неизвестном usage ошибочной попытки сохраняется `token_accounting_complete=false`; известные токены остаются нижней границей. Ошибочные попытки сохраняет gateway, который выполняет исходную попытку и до пяти технических повторов. Этот скрипт не добавляет повторы. Сетевую изоляцию проверяет операторский deployment readiness: решатель достигает только gateway; исследователь не достигает закрытых сервисов, каталогов и операторского MLflow.

Оператор копирует `config.example.json` вне этой папки, подставляет закреплённый image, реальные сети, пути и `campaign_id` новой кампании. Экспорт сохраняет этот идентификатор; старые состояния без поля относятся к первой кампании. Пути этой папки должны существовать по одинаковым абсолютным адресам у Docker daemon и у запускающего процесс оператора. `usage_dir` и `trace_dir` соответствуют `MODEL_USAGE_DIR` и `MODEL_TRACE_DIR` gateway. Используется уже замороженный пакет метрики; `ARENA_SC71_KB_ROOT` для судьи скрипт задаёт на синтетическую KB.

Запуск из корня репозитория после сборки образа, проверки сети и запуска gateway:

```bash
uv run python cases/sc71/acceptance/run.py \
  --config /operator/acceptance/config.json \
  --state /operator/acceptance/state.json \
  --scenario retrieval
```

После первого полного сценария оператор проверяет state и трейсы, рассчитывает ожидание оставшейся части согласно `common/long-runs.md` и запускает оставшиеся сценарии устойчивым заданием. Та же команда без `--scenario` последовательно завершает ещё не начатые сценарии. Уже начатый, завершённый, отклонённый или неудачный сценарий повторно не исполняется. Состояние записывается до запуска, сразу после ответа и после проверки; блокировка предотвращает параллельный дубль.

```bash
uv run python cases/sc71/acceptance/run.py \
  --config /operator/acceptance/config.json \
  --state /operator/acceptance/state.json
```

`--verify-only` проверяет сохранённые ответы по доверенным usage/traces без модели. Изменение конфигурации или файлов приёмки после начала блокируется. После сбоя адаптера сначала сохраните исходные свидетельства и разберите причину. Агент не создаёт новый state и не переименовывает эксперимент для повторного получения уже валидного ответа; новую отдельную серию экспериментов может назначить пользователь с сохранением прежней истории. Незавершённое после прерывания состояние `running` требует операторского разбора и не запускается автоматически. Итоги и ошибки остаются у оператора; никаких изменений реального private-реестра скрипт не делает.
