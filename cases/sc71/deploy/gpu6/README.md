# SC-71: GPU6

Это локально перенесённая конфигурация. Работающая кампания использует прежнюю серверную копию с `deploy/sc71/`; её нельзя синхронизировать, пересобирать или перезапускать этим пакетом. [Исторические свидетельства](../../../../archive/cases/sc71/campaigns/sc71-first-20261019/evidence/README.md) относятся только к той установке.

Операторский корень: `/cephfs/home/malyshev_sa/arena-sc71-first-20261019`. В исходной установке каталог `release` содержит проверенный код. `operator`, `secrets`, `logs` и `build` не передаются исследователю. Исследователь получает только очищенный `workspace`, разрешённые `assets` и `research-access` с submit-токенами и отдельным доступом к модели.

Для будущего отдельного развёртывания с этой структурой команда запуска имеет новый путь. Сейчас её выполнять не следует:

```bash
ssh gpu6 'bash /cephfs/home/malyshev_sa/arena-sc71-first-20261019/release/cases/sc71/deploy/gpu6/launch.sh'
```

Запуск создаёт постоянный контейнер `arena-sc71-researcher-1`. Повторный запуск без разбора предыдущего состояния отклоняется. Остановить новые предложения следует инструкцией оркестратору, сохранив уже начатые оценки; принудительное удаление контейнеров для штатной остановки не используется.

## Сервисы

| Доступ исследователя | Назначение |
| --- | --- |
| `http://train-evaluator:8080` | Полные измерения train |
| `http://public-evaluator:8080` | Общий score public |
| `http://private-evaluator:8080` | Отправка финалистов и статус |
| `http://shared-tracking:5000` | Только train и допустимые public-score |
| `http://researcher-gateway:8081` | Зафиксированная внутренняя модель; нужен scoped URL |
| `http://internet-proxy:3128` | Интернет для исследователей, с запретом внутренней адресации |

Submit-токены доступны в `/run/arena/{train,public,private}-token`. Ключ LiteLLM исследователь и решатель не получают. Операторские API привязаны к loopback GPU6: `18730`, `18731`, `18732`. MLflow с полными закрытыми результатами остаётся на `5050`; отдельное чистое исследовательское хранилище — на `5052`. Название эксперимента не используется как граница доступа.

## Изоляция

`sc71-researchers` и `sc71-workers` — внутренние Docker-сети. Исследователь не имеет Docker socket, SSH-ключей, закрытых данных, операторского окружения или доступа к сервисам хоста. Одноразовый решатель имеет только доступ к `model-gateway:8081`, текущий вопрос и разрешённые assets. Произвольный интернет решателю не выдаётся.

На GPU6 используется `iptables-legacy`; модуль `br_netfilter` включён для фильтрации трафика внутри мостов. `firewall.sh` меняет только выделенные цепочки и добавляет переходы из INPUT и DOCKER-USER. Трафик из подсетей арены разрешён только к перечисленным API; блокируются другие контейнеры, сервисы хоста и соседние workers. IPv6 у сетей должен быть отключён, `net.bridge.bridge-nf-call-iptables` должен равняться `1`. Запуск повторно устанавливает правила; проверка из реальных контейнеров является частью подготовки. Существующие рабочие нагрузки не останавливаются.

Модели embeddings/reranking исследователи могут выбирать после проверки требований. Веса загружаются исследователем в разрешённые материалы и замораживаются перед оценкой. GPU не назначается автоматически: узел занят другими задачами, а доступные карты — GTX 1080 Ti с 11 GiB памяти. Индексы, SQLite, деревья, README и любые представления KB строятся самим кандидатом и входят в измерения решения.

Для Hermes фиксируются Git-ревизия и версия образа. Профиль с `max_concurrent_children=30`, `oneshot_max_children=30`, глубиной 3, `reasoning_effort=max`, длинными таймаутами и пятью повторами общий для внешнего и внутренних Hermes. Фактические версии, проверки и готовность фиксируются в `cases/sc71/campaigns/sc71-first-20261019/preparation.md`.

В этой локальной конфигурации журнал `cases/sc71/campaigns/sc71-first-20261019/search.sqlite3` и рабочие записи кампании размещаются в Docker volume `sc71-campaign-runtime` на локальном диске GPU6. В новой конфигурации исследовательского контейнера volume монтируется по тому же логическому пути `/workspace/cases/sc71/campaigns/sc71-first-20261019`; SQLite не хранится на CephFS. Инициализация задаёт лимит 100 решений и ноль предложений.

Перед новым развёртыванием private-сервис получает этот volume только для чтения в `/search`, явный режим `ARENA_SEARCH_MODE=campaign`, ожидаемый лимит предложенных решений `ARENA_SEARCH_MAX_SOLUTIONS=100` и отдельный операторский каталог `operator/search`. До первого хода исследователя и при каждом возобновлении обязателен авторизованный `GET http://private-evaluator:8080/v1/search-readiness`: защита включена, журнал читается, лимит равен 100, `finalists` и `release_id` совпадают с зафиксированными условиями. Дата, команда и ответ без токена входят в свидетельства готовности; `/healthz` этого не заменяет. После отбора и ревью исследователь выполняет `evaluator.search finalize --bundle ...` с единым журналом. Сервис сверяет замороженный пакет, снимки, лимит предложенных решений и отсутствие выполняющихся проверок. При досрочной остановке требуется операторское свидетельство команды человека в `operator/search/stop.json` по [общему контракту](../../../../deploy/README.md); сам исследователь этот каталог не получает. Существующий private-допуск завершённой кампании эти настройки не переоткрывают.

Launcher исследователя получает явные `--journal`, `--private-url`, `--private-token-file`, `--private-finalists` и `--private-release-id`. Для новой установки оператор переносит в `operator/images.env` обязательные `SC71_FINALISTS` и `SC71_PRIVATE_RELEASE_ID` из уже зафиксированных условий: фактические K и release ID сохраняются, новые значения для обхода использованного допуска не создаются. Compose передаёт эти значения одновременно private-сервису как `ARENA_FINALISTS` и `ARENA_RELEASE_ID` и launcher как ожидаемые K и release ID. Одного `operator/evaluator.env` для интерполяции Compose недостаточно; отсутствие переменных отклоняется при разборе конфигурации. Launcher до создания агента проверяет серверную защиту, лимит предложенных решений из журнала и оба ожидаемых значения. Конец диалога Hermes при наличии свободных мест до лимита предложенных решений возвращает ему состояние поиска для продолжения. Повторное завершение без прогресса, ошибка инфраструктуры или преждевременно использованный private дают явное незавершённое состояние вместо успешного завершения кампании. Фиксированные модель, runtime и профиль Hermes этим не меняются.

## Явное подключение возможностей

Для отдельной новой установки образ evaluator собирается с `--build-arg ARENA_TRACKING=true`. Общий образ без этого параметра не включает SDK MLflow. Compose явно задаёт оба адреса MLflow и `MODEL_STRICT_SCHEMA_INTEGERS=true`: строгая запись целого числа нужна неизменённой метрике SC-71; общий gateway по умолчанию использует стандартную JSON Schema.

Профиль оценщиков явно включает `ARENA_RUNNER_SUPPORTS_BUILD=true` и `ARENA_RUNNER_SUPPORTS_ASSET_SELECTION=true`. При использовании реестра харнесов запись Hermes также должна содержать `supports_build: true` и `supports_asset_selection: true`. Для исходной KB оператор задаёт `SC71_INPUT_ASSETS_DIGEST`, передаваемый как `ARENA_INPUT_ASSETS_DIGEST`; идентификатор корпуса задаётся до запуска кампании. В общем протоколе это идентификатор разрешённых входных материалов, а KB — смысл именно SC-71.

В новой версии операция подготовки передаётся в верхнем поле `operation="build"`. Хранилище квитанций использует версию 2 и имя `input_assets_digest`. Старые квитанции и состояние работающей кампании не преобразуются на месте. На будущую установку передаются только отдельно подготовленные и проверенные образы, конфигурация реестра, хранилища и сети.

`launch.sh` проверяет `operator/layout-version` со значением `sc71-case-layout-v2` **до любых Docker-команд**. Старого `operator/READY` недостаточно. Маркер может создать оператор лишь после отдельного развёртывания, проверки нового протокола, образов, сети, прав, метрики и сервисов; этот репозиторий его не создаёт. Наличие старых исторических JSON не является основанием создать маркер. Новый запуск не разрешает новую private-попытку на использованном наборе.

Исходная кампания остаётся на `/workspace/runs/sc71-first-20261019` и старом протоколе. Не менять mount действующего `sc71-campaign-runtime` и не переносить его содержимое во время поиска.
