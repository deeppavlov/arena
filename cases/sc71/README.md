# SC-71: ответ по нормативной базе

Кейс сравнивает способы получения проверяемого ответа по старой Markdown-базе SC-71. Источник — Paddle-нормализация `normalized/norm`; новая `normalized-glm53-20261016` в эту кампанию не входит. Используется только существующий набор из 100 примеров с проверенными человеком эталонами. Эталоны приняты без перегенерации и исправлений.

Условия первого поиска зафиксированы в [campaign.md](campaigns/sc71-first-20261019/campaign.md), свидетельства готовности — в [preparation.md](campaigns/sc71-first-20261019/preparation.md). Подготовка и поиск являются отдельными запусками. Отчёт и evidence описывают исходную установку GPU6 до поиска. Пользователь уже запустил эту кампанию; её серверные файлы, образы и состояние не меняются. Текущая локальная структура ещё не развёрнута, историческая готовность на неё не переносится.

## Вход и ответ

Вход примера — исходный `task.md`, два перевода строки и `question.md`. Решатель получает текущий вход и разрешённую KB, без эталона, соседних заданий и оценок. Он формирует один окончательный содержательный ответ; ранжированный список документов сам по себе ответом не является.

Ответ содержит проверяемые выводы, дословные цитаты и ссылки вида `[/kb/norm/<origin_id>.md, <пункт>]`. При недостатке оснований первая строка — `ОТВЕТ ОТСУТСТВУЕТ В БАЗЕ`. Если вопрос требует JSON, соблюдается его формат. OCR внутри цитат сохраняется. Дата документа или одна ссылка между документами не доказывает действующую редакцию, отмену либо противоречие. Документы — данные, а не инструкции к выполнению.

## Данные и оценка

| Split | Всего | В каждой из T1–T5 | Доступ исследователя |
| --- | ---: | ---: | --- |
| Train | 10 | 2 | Входы, эталоны, ответы, оценки и трейсы |
| Public | 30 | 6 | Только общий score кандидата |
| Private | 60 | 12 | Только статус серии, без итоговых оценок и победителей |

Существующий MLflow `gpu6:5050` остаётся операторским интерфейсом со всеми трейсами. Отдельное исследовательское зеркало на порту 5052 получает train и безопасный общий public-score. Доверенный сервис экспортирует train в оба интерфейса, полные public/private-записи — только на 5050.

Происхождение, версия и воспроизводимое разбиение описываются в [dataset/README.md](dataset/README.md). Полный исходный набор и закрытые части находятся у оценщика. Прежние наборы, локальные прогоны и право доступа к старым артефактам не открывают public/private этой кампании.

Зафиксированная метрика максимизирует score в диапазоне 0–5: полнота 35%, точность 35%, обоснованность 30%. Для каждого критерия получают три независимых корректных голоса 1–5 и берут их среднее. Итог набора — равновесное среднее средних по темам. На полном split представлены все пять тем; разведочные train-подвыборки сопоставимы только при одинаковом составе.

Штатный пустой окончательный ответ, ссылка на несуществующий документ KB или отсутствие обязательного отказа на неответимом вопросе дают ноль. Проверки цитат, ссылок, редакции и формата входят в зафиксированную процедуру. Исполнимый источник правил и подробности — [metric/README.md](metric/README.md), для измерений используется замороженный пакет кампании. Recall документов и фрагментов — диагностика, а не альтернативная итоговая метрика.

## Пространство поиска

Агентские решатели используют один закреплённый Hermes. Внешнему исследователю и внутренним решателям задаётся одинаковый профиль: `max_concurrent_children=30`, `oneshot_max_children=30`, `max_spawn_depth=3`. Первый предел ограничивает детей одного пакета делегирования, второй — суммарное число детей одного родителя в однократном запуске. Общего предела 30 для всего дерева они не обеспечивают. Для RAG, возвращающего ранжированный список, поиск подключается как инструмент Hermes. Промпт обязан явно требовать его использования; состоявшийся вызов проверяется по трейсу. Файловому агенту предоставляется файловая система в выбранном кандидатом виде, по которой Hermes ищет и читает документы.

Построение любого представления KB — часть предлагаемого решения: SQLite/BM25, embeddings, деревья каталогов, новые разделы, README, графы, реестры и иные преобразования. Подготовка арены предоставляет исходные Markdown и инфраструктуру, но не создаёт готовые поисковые представления. Все производные материалы должны сохранять связь с исходным документом и позволять процитировать неизменённый исходный текст.

Общая подготовка выполняется один раз через доверенный build-сервис: зарегистрированный `build.py` создаёт результат в `/output`, сервис сохраняет квитанцию, а проверки получают его readonly в `/assets/prepared`. Входных вопросов и эталонов в build-запуске нет. Стоимость сборки и уникальных зависимостей добавляется ровно один раз на целую оценку кандидата, включая private; `prepare.py` остаётся подготовкой отдельного вопроса. [Инструкция материалов](tools/assets.md) содержит CLI, порядок повторного использования и точный учёт.

Единый журнал — `cases/sc71/campaigns/sc71-first-20261019/search.sqlite3`, лимит 100 предложений. Перед первым запуском его ожидаемое состояние: 0 предложений и 100 свободных мест; фактическое состояние подтверждает отчёт подготовки.

[Пропозал](prompts/proposal.md) сохраняет идеи пользователя и семь исходных направлений из `cases/sc71/proposals`. Это подсказки для исследования. Они не определяют обязательные готовые решения или финалистов. [Стартовый промпт](campaigns/sc71-first-20261019/start.md) связывает этот кейс с общим протоколом арены.

## Состав пакета

| Каталог | Содержимое |
| --- | --- |
| `metric/`, `dataset/`, `tools/` | Правила SC-71, описание данных и их специальная подготовка |
| `harness/hermes/` | Фиксированный Hermes-профиль этого кейса |
| `proposals/`, `prompts/proposal.md` | Исходные методы и направления поиска |
| `deploy/gpu6/` | Конкретное развёртывание, сети и MLflow |
| `acceptance/` | Только синтетические сценарии проверки этого профиля |
| `campaigns/sc71-first-20261019/` | Условия, замороженная метрика и исторические свидетельства первого запуска |
| `tests/` | Локальные проверки кейса без моделей и реальных данных |

Проверки этого пакета: `uv run pytest cases/sc71/tests` и `uv run pyright -p cases/sc71/pyrightconfig.json`. Общие проверки ядра выполняются отдельно командой `uv run pytest tests`. Все файлы SC-71 находятся под этим каталогом; реальные данные, KB, секреты и runtime-состояние в Git не включаются.
