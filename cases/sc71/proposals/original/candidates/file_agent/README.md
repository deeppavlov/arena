# №3. Агент, который ищет и читает документы

Подготовлено 16.10.2026. Самостоятельный локальный кандидат `file_agent`. Прежние пять кандидатов не изменяются. Реальный GLM в ходе реализации не запускался.

## Как это работает простыми словами

Первый поиск выполняется по исходному вопросу. Затем GLM видит найденные участки и выбирает одно действие: уточнить поиск, найти буквальную фразу, найти документ по реквизитам, посмотреть его структуру или прочитать конкретные строки. Результат действия поступает в следующий запрос GLM. Таким образом, следующее действие зависит от реально прочитанного текста. Например: положение → ссылка на приказ → поиск приказа → чтение изменения.

Это ограниченный агент с собственными инструментами, а не запуск внешнего кодинг-харнеса или свободной оболочки. Инструкция, которую получает модель: [AGENT.md](AGENT.md). Для контроллера используется JSON в обычном chat/completions; поддержка нативного tool calling не требуется. Нужна модель, способная соблюдать инструкцию и формат. С реальным сервисом это ещё предстоит проверить.

После не более четырёх действий общий генератор составляет ответ по отобранным исходным цитатам. Он не получает рассуждения контроллера или тексты каталога как доказательства. Модель ответа, её промпт и проверка цитирования переиспользованы из базового кандидата. Режим `extractive` выдаёт цитаты, а не полноценное решение.

## Что подготовлено в каталоге

В `assets/catalog-v1/` находится локальный каталог всех 4454 Markdown текущего корпуса. `catalog.jsonl` содержит одну запись на документ:

- `origin_id`, относительное имя Markdown;
- `original_path` из манифеста, если соответствие есть;
- название, предположительный тип, длина и число строк;
- собственные номер/дата, если они распознаны в шапке, и исходные координаты;
- количество узлов структуры; юридический статус всегда `unknown`.

Распознаны собственные реквизиты 607 документов. Исходный путь известен для 4440; у остальных 14 он оставлен неизвестным. Это характеристики эвристического извлечения, не проверенная точность. Первая ссылка на чужой приказ не подменяет собственные реквизиты. Манифест используется только как метаданные: пути из него никогда не открываются и не исполняются.

Каталог — отдельный подготовленный результат, **не готовый поисковый индекс**. Для поиска один раз выполните полную сборку ниже. Она создаёт SQLite с текстами, структурой, BM25 и таблицей каталога. Сам корпус и исходная структура папок остаются без изменений. Для другого корпуса каталог пересоздаётся из его файлов.

## Запуск в Git Bash

Команды выполняются из корня `deus-ex-harness`. Нужен CPython 3.12; внешних runtime-зависимостей нет. Для Linux замените путь Python на `.venv/bin/python`.

```bash
PYTHON=".venv/Scripts/python.exe"
WORK="artifacts/SC-71/kryukova"
C="$WORK/candidates/file_agent"
```

Сначала можно посмотреть работу без настоящей модели на искусственных документах:

```bash
"$PYTHON" -B "$C/build.py" --kb-dir "$C/examples/norm" \
  --build-dir "$C/checks/my-example-index-v1"
"$PYTHON" -B "$C/run.py" --build-dir "$C/checks/my-example-index-v1" \
  --question "Кто согласует закупку?" --no-agent --format json
```

Полный индекс своего корпуса, без модельных запросов:

```bash
"$PYTHON" -B "$C/build.py" --kb-dir "$WORK/data/normalized/norm" \
  --build-dir "$C/assets/index-v1"
```

Каталог и индекс версионируются: непустой каталог сборки не перезаписывается. Для одной выгрузки каталога доступен `--catalog-only` с отдельным новым build-dir. По умолчанию `manifest.json` ищется рядом с `norm/`; иной файл задаётся через `--source-manifest`. Без манифеста исходные пути останутся неизвестными.

**Следующая команда уже обращается к GLM**, до четырёх логических запросов:

```bash
"$PYTHON" -B "$C/run.py" --build-dir "$C/assets/index-v1" \
  --env-file "$WORK/.env" --question "Ваш Public-вопрос" --format json \
  > "$C/checks/my-public-retrieval.json" 2> "$C/checks/my-public-retrieval-trace.json"
```

Для ответа уберите `--format json`. Будет ещё один запрос общего генератора. При повторном запуске поиск и модельные действия выполняются заново: готовый retrieval JSON сам по себе не является кэшем для `run.py`. Не повторяйте валидные генерации ради лучшего балла. Команды здесь являются инструкцией, не протоколом автоматически разрешённого большого эксперимента.

В `.env` нужны `SC71_CHAT_URL` (полный chat/completions URL), `SC71_CHAT_MODEL` и `SC71_CHAT_KEY`. Сам файл и ключ не входят в пакет. Настройки `settings.json` закрепляются при сборке. Для `reasoning_effort=low` совместимость с лабораторной GLM пока не проверена; если параметр не поддерживается, задайте `null` и соберите новую версию индекса, зафиксировав отличие. Автоматического переключения модели нет.

## Ограничения и формат

- До 4 дополнительных модельных запросов; температура 0, ответ контроллера до
  2048 токенов, отдельный timeout 600 секунд на запрос. Общий ответ — до 8192.
- Начальный вопрос до 16000 символов ищется целиком. Уточнения — до 600.
- Один результат инструмента до 6000 символов сериализованного JSON, сумма
  наблюдений до 24000. Записи удаляются целиком с признаком `truncated`;
  исходные цитаты не обрезаются незаметно.
- Чтение до 40 строк и 4000 символов; `read_span` позволяет читать длинные строки.
  `grep` ищет буквальную подстроку без учёта регистра, не регулярное выражение.
- Финальный контекст: до 8 исходных участков, до 3 на документ, до 16000 символов
  цитат вместе с повторяемыми шапками. Инструкция, вопрос и JSON-обвязка учитываются
  отдельно через usage модели. Полученные вручную чтения имеют приоритет над поиском.
- `char_start` с нуля, `char_end` исключена; строки с единицы включительно.
  Координаты относятся к UTF-8 тексту после удаления BOM, исходные CRLF сохраняются.
  `/kb/norm/<id>.md` — логический адрес цитаты, не требование к локальным папкам.
- Инструменты читают только замороженный SQLite, принимают ID, а не пути. При
  исполнении пакет и индекс не изменяются.
- stdout: ответ либо retrieval JSON; stderr: один диагностический JSON. Подробные
  действия есть в retrieval JSON; stderr содержит их статусы, координаты и
  usage без текста документов, запросов инструментов и ключа. Локальные результаты
  могут содержать закрытые сведения и не предназначены для публикации.
- Некорректный ответ модели сохраняется в stdout, отмечается в stderr, код выхода 2.
  Ошибка контроллера не скрывается заменой на baseline. Сохраняются частичные расходы.
  Учёт вызовов логический: транспорт допускает технические повторы только 503 с
  `Retry-After`; число физических попыток и расходы неуспешных запросов неизвестны.

`--no-agent` возвращает полноценный структурный поиск без контроллера. Это сильная база сравнения; у агента начальный видимый поиск ограничен бюджетом инструмента, поэтому сравнение является сравнением систем, а не чистой оценкой пользы итераций. Сопоставляйте одинаковые Public ID, генератор, судью и конечный бюджет контекста; время и токены дополнительных чтений показывайте отдельно.

Каталог извлекается эвристически: нет гарантированного издателя, полной временной модели, восстановления OCR и общего юридического вывода об актуальности. `lookup` по номеру/дате требует распознанных собственных реквизитов; при их отсутствии остаются поиск, буквальное совпадение и чтение. Модель может пропустить нужный документ или потратить шаги впустую. Преимущество на SC-71 ещё не измерено.

## Файлы и передача

`candidate.py` — контроллер и инструменты; `catalog.py` — каталог; `AGENT.md` — инструкция; `lexical.py`/`structure.py` импортируют общий структурный поиск; `baseline.py`/`common.py` импортируют базовый код из `retrieval/`; `runtime.py`, `build.py`, `run.py` — локальный интерфейс; `settings.json` — параметры; `requirements.lock` — runtime, `requirements-dev.txt` — проверки; `examples/` — искусственный корпус; `tests/` — тесты; `checks/` — свидетельства; `RESEARCH.md` — гипотеза и план измерения; `assets/` — локальные производные данные.

`candidate.json` описывает прежний локальный build/run интерфейс. **Это не адаптер актуальной Arena.** Её JSON stdin, разрешённые assets, образ и модельный интерфейс нужно отдельно согласовать и проверить. Реальное сквозное исполнение Arena отложено. Для передачи переносим код без `assets/` и закрытых трейсов; каталог/индексы предоставляются только разрешённым способом. Весь `artifacts/` игнорируется Git.

Проверки и воспроизводимые команды: [checks/VALIDATION.md](checks/VALIDATION.md).
