# №4. Норма вместе с основаниями изменения

Подготовлено 16.10.2026. Самостоятельный локальный кандидат `amendment_bm25`. Не требует BGE, GPU, отдельного сервиса или настоящей структуры папок gpu12. Существующие кандидаты не изменены.

## Что делает метод

Сначала выполняется структурный BM25 с восстановлением ограниченного окружения. Для документов из первых трёх результатов ищутся входящие и исходящие связи: какой акт изменяет найденный документ и на что ссылается сам найденный акт. В контекст резервируется комплект: исходное распоряжение об изменении + участок документа, на который оно направлено. Затем добавляется оставшаяся поисковая выдача.

Пример: найден старый пункт «согласование выполняет директор». Реестр приводит к приказу с формулировкой «пункт 2 изложить в следующей редакции… ректор». Генератор видит оба исходных участка и их координаты. Наличие такого приказа не означает, что код сам установил действующую редакцию: даты вступления, последующие изменения и юридическая применимость требуют проверки содержания.

## Каталог и реестр

В `assets/catalog-v1/` подготовлены результаты на текущем корпусе 4454 Markdown:

- `catalog.jsonl` — ID, название, исходный путь из манифеста, собственные реквизиты
  с координатами, размер и структура; `catalog-summary.json` — сводка;
- `relations.jsonl` — типизированные ссылки с точной исходной цитатой,
  координатами, реквизитами адресата и результатом сопоставления;
- `relations-summary.json` — число ссылок по типам и статусам разрешения.

Реквизиты собственной шапки удалось распознать у 607 документов; исходный путь известен для 4440. Неизвестные данные не достраиваются из предположений. Каталог уже готов, поисковый SQLite нужно собрать отдельной командой ниже.

Типы: `mentions` — упоминание, `amends` — явная формулировка изменения, `repeals` — явная формулировка отмены/утраты силы. Для изменений проверяются повелительные формулировки «внести», «изложить», «дополнить», «исключить»; для отмены — «отменить» или «признать утратившим силу». Название «О внесении изменений» само по себе действием не считается. Отрицания учитываются.

Адресат сопоставляется по виду акта, номеру и дате. `unique` означает одно совпадение в этом каталоге, а не юридически подтверждённую идентичность: издатель не установлен. `ambiguous` и `missing` сохраняются в реестре, но в расширении поиска не участвуют. При нескольких ссылках в одной операционной формулировке связь консервативно остаётся упоминанием. Определения «изменяет» и «отменяет» являются результатом текстового правила, не юридической экспертизой. У всех записей `legal_status=unknown`.

Распознаются ссылки с датами `ДД.ММ.ГГГГ` и номером, в прямом и обратном порядке. Не реализованы все варианты русских дат, сокращений, OCR-искажений, неоднозначных приложений и связей вида «Положение, утверждённое приказом…». Отсутствие связи не доказывает отсутствие изменения. Это отдельный специализированный соперник `linked_hybrid`, а не полная правовая база и не векторный GraphRAG.

## Запуск в Git Bash

Из корня `deus-ex-harness`, CPython 3.12, без внешних runtime-зависимостей. Для Linux замените путь Python на `.venv/bin/python`.

```bash
PYTHON=".venv/Scripts/python.exe"
WORK="artifacts/SC-71/kryukova"
C="$WORK/candidates/amendment_bm25"

"$PYTHON" -B "$C/build.py" --kb-dir "$C/examples/norm" \
  --build-dir "$C/checks/my-example-index-v1"
"$PYTHON" -B "$C/run.py" --build-dir "$C/checks/my-example-index-v1" \
  --question "Кто согласует закупку по приказу 10-1?" --format json
```

Поиск полностью локальный. Сборка реального индекса тоже не вызывает моделей:

```bash
"$PYTHON" -B "$C/build.py" --kb-dir "$WORK/data/normalized/norm" \
  --build-dir "$C/assets/index-v1"
"$PYTHON" -B "$C/run.py" --build-dir "$C/assets/index-v1" \
  --question "Ваш Public-вопрос" --format json \
  > "$C/checks/my-public-retrieval.json" 2> "$C/checks/my-public-trace.json"
```

**Следующая команда делает один логический запрос генератора ответа к GLM:**

```bash
"$PYTHON" -B "$C/run.py" --build-dir "$C/assets/index-v1" \
  --env-file "$WORK/.env" --question "Ваш Public-вопрос"
```

Модель задаётся `SC71_CHAT_MODEL`, полный маршрут — `SC71_CHAT_URL`, ключ — `SC71_CHAT_KEY`. Промпт генератора и проверка цитат общие с базовыми кандидатами. При недостатке оснований он должен обозначить неопределённость. Юридический ответ не выводится автоматически из номера, даты или типа ребра.

`--no-relations` отключает расширение и возвращает ровно структурный baseline с теми же настройками. `--catalog-only` у `build.py` готовит только каталог и реестр, без поискового индекса. Непустые каталоги сборки не перезаписываются. `--source-manifest` задаёт иной манифест; по умолчанию берётся соседний с `norm/`.

## Бюджет и проверяемость

- Первые 3 поисковых участка сохраняются, проверяется до 4 связей глубины 1.
  Упоминания по умолчанию не расширяются. Это настраивается до новой сборки.
- Если пункт адресата найден однозначно по номеру и помещается в 3600 символов,
  берётся целиком. Иначе выбирается поисковый контекст адресата с явным
  `target_scope_located=false`; он не объявляется точным изменённым пунктом.
- Длинное основание возвращается ограниченным исходным окном с
  `evidence_complete=false`. Полная цитата и координаты остаются в реестре.
- Комплект добавляется целиком или пропускается из-за бюджета; ссылки без
  включённых в контекст оснований не передаются генератору.
- Итог до 8 участков, до 3 на документ; до 16000 символов цитат, повторяемых
  шапок **и сериализованных метаданных связей**, из них связям не более 2500.
  Текст инструкции, вопрос и прочая JSON-обвязка учитываются отдельно через usage.
- Символы с нуля, правая граница исключена; строки с единицы включительно.
  UTF-8 BOM удаляется при декодировании, CRLF сохраняются. Цитаты дословные.
- При исполнении индекс открывается только для чтения. Пакет и индекс не требуют записи.
- stdout содержит ответ или retrieval JSON; stderr — диагностический JSON.
  Ошибочный сгенерированный ответ сохраняется и отмечается кодом выхода 2,
  без повторной генерации. Ключ не попадает в диагностику.

## Как сравнивать и что пока неизвестно

Baseline — `structure_bm25` и `--no-relations`, затем добавление реестра при одинаковых Public ID, контексте, генераторе и судье. Измерять полноту исходных доказательных участков и качество ответа, отдельно случаи T1/T4, неверные редакции, лишние основания, задержку и размер индекса. Для Recall@k сначала нужна разметка единых исходных участков, независимая от стратегии нарезки.

Синтетические проверки подтверждают исполнение и координаты. Ручная проверка реальных извлечённых связей, качество поиска и ответа на Public, расходы GLM, преимущество над прежними кандидатами **ещё не измерены**. Не все документы имеют распознанные реквизиты; выдача может пропустить важное изменение.

`candidate.py` — поиск и упаковка комплектов; `relations.py` — извлечение связей; `catalog.py` — каталог; `lexical.py`, `structure.py`, `baseline.py`, `common.py` — совместимые импорты общих компонентов `retrieval/`; `runtime.py`, `build.py`, `run.py` — CLI; `settings.json` — настройки; `examples/`, `tests/`, `checks/` — примеры и проверки; `RESEARCH.md` — исследовательская запись. Новые каталоги и исходники игнорируются Git вместе с `artifacts/`; доступность команде нужно согласовать.

`candidate.json` — локальный build/run интерфейс. Адаптер актуальной Arena и сквозное исполнение в её образе не проверялись. Отдельно потребуются согласование assets, моделей и текущего контракта. В пакет для публикации нельзя включать клиентский каталог, тексты, private или закрытые трейсы.
