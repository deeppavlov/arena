Имеющиеся Markdown- и JSON-эталоны считаются утверждёнными пользователем и сохраняются без изменений. Историческое поле `ground_truth_origin=model_reviewed` также сохраняется в исходном манифесте.

Разрешённый исходный корпус — прежний Paddle: `gpu6:/cephfs/home/malyshev_sa/sc71-kb/normalized/`, версия `v1.1-raw`, `snapshot-2026-09-08-full`, 4454 файла `norm/<origin_id>.md`. Новый корпус GLM не используется. Подготовка не создаёт SQLite, векторный индекс или иное поисковое представление: их построение относится к методам будущей кампании.

## Операторская подготовка

Для уже запущенной кампании повторная подготовка не выполняется: split и эталоны остаются прежними. Команда ниже предназначена для отдельной установки, не для перезаписи рабочего GPU6.

Команда выполняется на Python 3.12 или новее внутри доверенного контура. Исходный полный набор нельзя монтировать исследователю, помещать в репозиторий, образы или общедоступный MLflow. Пути ниже — пример расположения; все входные и выходные каталоги должны быть раздельными, а оба выходных каталога ещё не должны существовать.

```bash
python cases/sc71/tools/prepare_dataset.py \
  --source /srv/arena/operator/source/sc-71-deepseek-hermes \
  --kb-root /srv/arena/assets/kb \
  --train-output /srv/arena/workspace/cases/sc71/dataset/train \
  --closed-output /srv/arena/operator/dataset \
  --seed sc71-first-20261019
```

Скрипт проверяет точные 100 идентификаторов, пути исходных файлов, совпадение идентификаторов и тем эталонов, статус `validated`, ссылки на документы, дословность эталонных цитат после схлопывания пробелов и наличие каждого Markdown в `index.tsv`. Исходные пути документов сверяются с индексом и манифестом корпуса. Symlink в исходных файлах запрещён. Все проверки данных проходят до создания выходных каталогов. Содержимое вопросов, эталонов и цитат не выводится даже при ошибке.

Результат:

- `<train-output>/dataset.jsonl` и оригинальные файлы только десяти train-примеров;
- `<closed-output>/public/dataset.jsonl` и `<closed-output>/private/dataset.jsonl`;
- в каждом разделе `source/` с исходными байтами и `manifest.json` с составом раздела, путями исходных файлов и `dataset.jsonl`;
- `<closed-output>/source-manifest.json` и полный закрытый `manifest.json`;
- `<train-output>/summary.json` и stdout с безопасными размерами, seed и путями файлов разделов, без закрытых идентификаторов и содержимого.

Каталоги создаются с правами `0700`, файлы — `0600`. Оператор передаёт исследовательской учётной записи только train и разрешённую KB, сохраняя public/private и полный исходный манифест в закрытом контуре. `validation_evidence`, исходные прогоны и отчёты не экспортируются.

Каждая строка JSONL соответствует `evaluator.contracts.Example`: `id`, `input`, `reference`. Вход — исходный `task.md`, два перевода строки и исходный вопрос. Эталон — JSON-строка с `format="sc71-reference-v1"`, `topic`, `reference_markdown` и исходным объектом `gold`. Эта обёртка нужна метрике; решатель получает только `input`. Для метрики `ARENA_SC71_KB_ROOT` указывает на корень корпуса, содержащий `norm/`.

Подготовка ничего не оценивает, не вызывает модели и не расходует private-допуск.

Безопасные размеры и описание подготовленного набора сохранены в [manifest.json](manifest.json). Этот файл не содержит закрытых идентификаторов, вопросов, эталонов или результатов оценивания.
