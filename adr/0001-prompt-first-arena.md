# ADR-0001: универсальная арена из промптов и отдельный private evaluator

Дата: 2026-10-11. Статус: принято для начальной реализации.

## Основание

Приоритет требований: уточнения владельца 11.10.2026, схема на второй странице `DeepPavlov-3-5 (1).pdf` и обсуждение 08.10.2026, затем прежние документы арены. Новая арена живёт в отдельном репозитории `arena`; привязка к SC-71 и прежнему исполнительному харнесу не переносится.

## Решение

Public-часть — универсальные промпты, шаблоны кейса и file-first результаты. Запускать их можно из чата, Codex, Hermes или другого инструмента с необходимыми правами и внутренней моделью. Оркестрация, разделение ролей, работа в отдельных ветках и сохранение findings задаются [протоколом](../common/research-protocol.md), [оркестрацией](../common/orchestration.md) и [IMMUNE](../common/IMMUNE.md). Отдельный SDK харнеса не вводится.

Кейс определяет постановку, public-входы, критерии, эталоны, baseline и разрешённые изменения. До кампании фиксируются модель, харнес, параметры, версия датасета и оценщика. Исследователь может выбирать public-подмножества для разведки; сравнение финалистов выполняется на общем закреплённом public-наборе.

Все вызовы моделей над обеими частями датасета используют внутреннюю инфраструктуру. Решатель и судья используют одну фиксированную модель, но независимые контексты. На каждый пример создаётся один ответ; каждый критерий этого ответа получает три независимые оценки отдельными запросами. Метрика — адаптация варианта 3 с заранее подготовленным усиленным синтетическим эталоном, без A/B и исходников у судьи. Средние и взвешенную сумму считает код. Эталоны не генерируются во время оценки кандидата.

Public API принимает одним batch заранее установленное оператором число замороженных финалистов: от одного до пяти, по умолчанию пять. Private evaluator самостоятельно проверяет весь закреплённый private-набор. Журнал на диске обеспечивает один допуск для датасета и идемпотентную доставку того же batch: повтор возвращает прежний статус без нового запуска. Прерванная серия завершается статусом `failed`; API восстановления и сброса нет. Частичные результаты не раскрываются. Итоговая оценка всей серии завершает кампанию и не становится циклом подгонки под private. При равных лучших оценках единственный победитель не объявляется (`winner: null`).

Private evaluator и его датасет находятся в отдельном контейнере; код кандидата выполняется в ещё одном одноразовом контейнере на пример. Worker получает текущую задачу и разрешённые ресурсы, но не эталон, весь датасет, ключ модели или Docker socket. Внутренняя модель доступна через узкий gateway. Только доверенный оценщик управляет Docker daemon. Полная граница доверия описана в [isolation.md](../common/isolation.md).

MLflow — средство наблюдения public-экспериментов; существующий адрес `gpu6:5050` задаётся конфигурацией. Локальные артефакты и private-журнал остаются источником состояния. Доступ исследователя к приватным трассам через общую MLflow-инсталляцию не допускается.

## Следствия

Универсальность обеспечивается контрактом кейса и промптами. Минимальный исполняемый адаптер кандидата нужен только для воспроизводимого закрытого прогона; пример адаптера не объявляется фиксированным харнесом всех будущих кейсов. Его image и зависимости выбирает оператор до кампании.

Запуск из привилегированного чата не даёт приватности относительно этого чата. Для изоляции его инструменты ограничиваются public-частью, а private-сервис и операторская учётная запись отделяются. Контейнеры разделяют ресурсы, но не скрывают данные от администратора Docker или хоста.

Эта поставка готовит репозиторий, локальные проверки и контейнерные определения. Она не создаёт реальные датасеты, не вызывает внутренние модели, не запускает кампанию и не развёртывает сервисы на кластере.
