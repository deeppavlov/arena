# Подготовка контейнерного запуска

Команды ниже предназначены для последующего запуска оператором. Подготовка репозитория не развёртывает кластер и не запускает модели. Сначала прочитайте [границу private](../common/isolation.md).

## Размещение и права

Профиль `public` запускается на рабочем узле исследователя; профиль `private` — на доверенном узле. Это могут быть один физический сервер с раздельными правами или разные серверы. Исследователь не получает SSH shell приватного оператора, доступ к Docker daemon, приватным каталогам или журналам модельного сервера.

Конфигурацию оператора копируют из `deploy/operator.env.example` в `/etc/arena/operator.env`, вне checkout и public workspace. В ней только настройки и пути; ключи находятся в отдельных файлах. Не передавайте весь этот env публичному контейнеру. Приватный каталог никогда не должен попадать в Docker build context или публикуемый Git-репозиторий.

| Путь по умолчанию | Содержимое и права |
| --- | --- |
| `/srv/arena/public` | Отдельная чистая public-копия репозитория и результаты; UID 10001 может писать |
| `/srv/arena/private/dataset.jsonl` | Private JSONL: `id`, `input`, `reference`; только оператор и UID 10001 читают |
| `/srv/arena/private/metric.json` | Зафиксированная метрика с вопросами по критериям; read-only |
| `/srv/arena/state` | Постоянный закрытый журнал и результаты; владелец UID 10001, режим 0700 |
| `/srv/arena/usage` | Журнал расхода решателя; UID 10001, режим 0700, доступ только evaluator и gateway |
| `/srv/arena/assets` | Только разрешённые всем кандидатам ресурсы; каталоги 0755, файлы 0644, read-only |
| `/srv/arena/secrets/submit-token` | Длинный случайный bearer token API; отдельный файл, читает UID 10001 |
| `/srv/arena/secrets/model-api-key` | Ключ внутренней модели, читает UID 10001; не передаётся runner |

У каталогов private/secrets ограничьте проход оператором; bind mounts отдельных файлов позволяют оценщику прочитать их при правильном UID. Для внутреннего API без авторизации создайте пустой файл model-api-key. Submit token должен быть непустым и непредсказуемым. Токен позволяет только отправку и чтение статуса закреплённого допуска; API не предоставляет административных операций.

`ARENA_STATE_DIR` и `ARENA_ASSETS_DIR` — абсолютные пути, одинаковые внутри evaluator и на Docker-хосте. Оценщик передаёт их Docker daemon для bind mounts кандидата: замена container path на `/state` сломает эту связь. Docker daemon должен работать на том же узле, где лежат эти файлы. Не используйте сетевой Docker context или SSH `DOCKER_HOST` для этого Compose.

`ARENA_USAGE_DIR` — отдельный каталог счётчиков, общий только для evaluator и gateway. Создайте его до запуска с владельцем UID 10001 и режимом 0700. Не помещайте его в assets или public workspace и не монтируйте в runner. Для каждого решения evaluator создаёт отдельный случайный идентификатор учёта; gateway принимает только заранее зарегистрированные обращения и сохраняет расход всех попыток, включая подготовку контекста. Значения ресурсов из stdout кандидата не используются.

Assets должны быть неизменяемым снимком на всю кампанию; зафиксируйте их digest в описании кейса. Оценщик сохраняет путь assets, но не пересчитывает содержимое больших внешних ресурсов. Read-only mount не защищает от изменения файлов оператором на хосте.

`ARENA_DOCKER_GID` задаётся фактической группой сокета (`stat -c '%g' /var/run/docker.sock`), а `ARENA_DOCKER_SOCKET` — его путём. Только evaluator получает этот socket. Файл модели, метрика и состояние не монтируются в public или gateway. Submit credential при необходимости выдаётся исследователю отдельно от операторской конфигурации.

## Заморозка исполнения

Перед запуском заполните `ARENA_MODEL`, внутренний `ARENA_MODEL_BASE_URL` с окончанием `/v1`, `ARENA_PARAMETERS` в JSON, `ARENA_RELEASE_ID` и digest runner image. Модель и параметры одни и те же для решателя через gateway и судьи. Во всей кампании сохраняйте тот же харнес и image. Документация конкретного runner находится в [runner/README.md](../runner/README.md).

Соберите операторский runner отдельно, затем укажите его content digest в `ARENA_RUNNER_IMAGE`. Тег `latest` и другие изменяемые теги оценщик отвергает. Для локального образа можно получить неизменяемый ID командой:

```bash
docker image inspect arena-runner:local --format '{{.Id}}'
```

Зафиксируйте также базовые Docker images по digest при подготовке воспроизводимого релиза. Dockerfile устанавливает зависимости из `uv.lock` через `uv sync --frozen`; теги базовых образов в исходном шаблоне остаются выбором оператора. [Документация uv](https://docs.astral.sh/uv/concepts/projects/sync/).

## Длительная работа

Все интервалы в env задаются в секундах; значения должны быть конечными и положительными, задержка повторов допускает ноль. Один первоначальный запрос к модели имеет пять повторных попыток при сетевой ошибке, ошибке HTTP или некорректном ответе. Судья также повторяет невалидную оценку. Уже принятый ответ или валидная низкая оценка не перегенерируются. Паузы по умолчанию: 30, 60, 120, 240 и 300 секунд.

| Переменная | По умолчанию | Что ограничивает |
| --- | --- | --- |
| `ARENA_MODEL_TIMEOUT` | `21600`, 6 часов | Одну попытку решателя или судьи |
| `ARENA_RETRY_DELAY` | `30` | Начальную задержку повтора; последующие удваиваются до 300 секунд |
| `ARENA_PREPARE_TIMEOUT` | `172800`, 48 часов | Подготовку контекста комплектного раннера |
| `ARENA_RUNNER_TIMEOUT` | `604800`, 7 суток | Полное решение одного примера, включая подготовку и повторы |
| `ARENA_EVALUATOR_TIMEOUT` | `3600`, 1 час | HTTP-запрос клиента `submit/status`, не всю приватную серию |

Комплектный раннер ждёт gateway дольше суммарного времени всех шести попыток и задержек: при этих настройках 130410 секунд. В gateway модельный таймаут ограничивает общее время одной попытки; у судьи это таймаут сетевых операций HTTP-клиента. При увеличении модельного таймаута увеличьте и внешний лимит раннера так, чтобы он покрывал подготовку и все вызовы выбранного харнеса. Общее время обработки датасета этими значениями не ограничено. Отдельные короткие таймауты healthcheck и очистки контейнеров не ограничивают генерацию модели.

Внешний reverse proxy, модельный сервер, кластерная очередь и среда исследовательского агента также должны разрешать такие длительности. Настройки арены не меняют ограничения этих служб. Пользователю следует увеличить допустимую глубину вложенности субагентов, если выбранная среда это поддерживает, и время их работы до длительности исследования. Правила ожидания без промежуточных обращений к проприетарной модели описаны в [длительных запусках](../common/long-runs.md).

Сервер модели должен возвращать достоверный `usage`: число входных и выходных токенов. Успешный ответ без этих измерений считается некорректным и повторяется. При обрыве без `usage` реальный расход неизвестен: он отмечается отдельным счётчиком, а не нулём. Измерения решателя и судьи сохраняются отдельно; для выбора при равном качестве используются ресурсы решателя по [общему правилу](../common/research-protocol.md).

## Private-сервис

```bash
docker compose --env-file /etc/arena/operator.env --profile private config --quiet
docker compose --env-file /etc/arena/operator.env --profile private build
docker compose --env-file /etc/arena/operator.env --profile private up -d
```

Compose публикует evaluator только на `127.0.0.1:8080`; gateway не публикует порты. `/healthz` подтверждает запуск процесса, а не доступность модели. Для удалённой отправки поставьте TLS reverse proxy с ограничением тела запроса и времени ответа либо выдайте туннель к единственному API-порту. Обычный SSH-ключ оператора исследователю не подходит: туннельная учётная запись должна запрещать shell, чтение файлов и перенаправления к другим адресам.

Сеть worker `arena-runners` является `internal`; к ней подключены только gateway и краткоживущие runner. Private evaluator подключён к `backend`. До реальных данных оператор проверяет firewall: worker не должен достигать служб хоста, других Docker-сетей, публичного интернета или модельного upstream в обход gateway. Сетевые правила кластера разрешают backend выход только к выбранному внутреннему API. Это операторская настройка сети, Compose сам её на хост не устанавливает.

Для первого приёмочного запуска используйте искусственные данные и искусственный кандидат. Проверьте запреты на чтение private, socket, host-служб и upstream; затем доступ через gateway, лимиты ресурсов, отказ второму batch, сохранение допуска после рестарта и отсутствие private-деталей в API. Мок-тесты репозитория не заменяют эту проверку конкретного Docker-хоста.

После исчерпания пяти повторов ошибочного модельного запроса серия получает `failed`; процесс оценщика продолжает обслуживать API. После прерывания процесса активная серия также получает `failed`. Повторная доставка того же batch возвращает сохранённый статус, а не запускает его заново. Автоматического продолжения после перезапуска и API retry/reset нет. Оператор разбирает причину в приватном журнале; допуск остаётся закрытым, частичные результаты исследователю не выдаются.

Не удаляйте state после раскрытия оценки и не используйте новый release ID как способ повторно отправить изменённых кандидатов на тот же holdout. Оператор хранит state и историю раскрытий при переносе сервиса. Новая исследовательская кампания требует независимого holdout либо явно отдельного протокола повторного использования.

## Public-контейнер

В `ARENA_PUBLIC_WORKSPACE` должна лежать чистая копия с public-данными, без `/etc/arena/operator.env`, ключей, приватного state и ссылок на приватные материалы. Простой mount текущего каталога оператора не является безопасной настройкой. Python и промпты уже есть в image; необходимый CLI-харнес оператор добавляет в свой зафиксированный image или работает из ограниченного чата.

```bash
docker compose --profile public build public
ARENA_PUBLIC_WORKSPACE=/srv/arena/public docker compose --profile public run --rm public
```

Из public-контейнера доступны только его workspace и публичная сеть. Прямой доступ к внутренним моделям для public-прогонов оператор настраивает отдельно; private gateway для него не открыт. Все операции над public-данными также выполняются внутренними моделями. Не вставляйте данные в облачный чат только потому, что он выступает оркестратором. Public-сеть в шаблоне имеет egress; ограничение разрешённых адресов задаёт инфраструктура оператора.

Public-MLflow по умолчанию — `http://gpu6:5050`. Его наличие, авторизация и политики доступа при подготовке репозитория не проверялись. Private-сервис туда автоматически ничего не отправляет. Конфигурация и шаблоны не содержат реальных ключей или датасетов.
