# Подготовка контейнерного запуска

Команды предназначены для оператора. Перед исследовательским поиском [агент подготовки](../prompts/prepare.md) готовит кейс, метрику, проверки и описание условий кампании. Оператор проверяет подготовленный код, устанавливает его в закрытом окружении и запускает оценщики. Подготовка репозитория сама не развёртывает сервис и не запускает модели. Сначала прочитайте [границы доступа](../common/isolation.md).

## От подготовки к запуску поиска

1. Пользователь описывает задачу и желаемую оценку в `cases/<case>/metric/`, указывает допустимые изменения, лимит решений и размеры входа/выхода private. Агент подготовки оформляет кампанию, реализует программную, модельную или смешанную оценку и проверяет её на открытых искусственных примерах. Модельные ответы в таких тестах подставные; реальные модельные эксперименты требуют отдельной задачи и зафиксированного числа решений.
2. Подготовленный каталог содержит `metric.json`, код, рубрики и ресурсы. Выполните его семантические тесты, затем заморозьте пакет. Каталог результата должен быть новым:

   ```bash
   uv run python -m evaluator.prepare freeze \
     --metric cases/my-case/metric --output runs/my-campaign/metric
   uv run python -m evaluator.prepare verify --metric runs/my-campaign/metric
   ```

   `freeze` и `verify` проверяют формат и целостность; они не выполняют оценку и не доказывают её качество. Готовые примеры лежат в `cases/template/metric/` и `cases/template/metric-examples/`. Их проверяет `uv run pytest tests/test_metric_examples.py` без моделей.
3. Установите весь пакет, включая `metric.lock.json`, в `/srv/arena/metric`. Установите зависимости команды в доверенный образ evaluator и закрепите образ и зависимости. Одинаковый замороженный пакет и окружение используются на train, public и private. Оператор подключает закрытые JSONL отдельно; в метрике, образе и исследовательской копии их нет. Не передавайте подготовительному агенту закрытые данные для реализации метрики.
4. Настройте окружение, runner, постоянное состояние и доступы по следующим разделам. После сборки проверьте пакет именно в окружении evaluator:

   ```bash
   docker compose --env-file /etc/arena/operator.env --profile private build
   docker compose --env-file /etc/arena/operator.env --profile private run --rm --no-deps \
     evaluator python -m evaluator.prepare verify --metric /private/metric
   ```

   Проведите приёмку в отдельном временном сервисе с собственными state/usage и токеном, искусственными данными и подставной моделью: верные и неверные ответы, программная агрегация, ошибки, учёт ресурсов, границы API и рестарт. Приёмка не расходует допуск настоящего private и не использует его данные.
5. Запустите нужные public/private-сервисы и зафиксируйте готовность в `runs/<campaign>/preparation.md`. В записи нужны digest пакета и окружения, пройденные проверки, условия кампании и доступные исследователю URL. `/healthz` подтверждает только живой процесс, не корректность метрики или доступность модели. При пустом public отдельный public-сервис не нужен. Формально оценщик нужен к первому обращению, но готовность всех нужных оценщиков проверяется до начала поиска.
6. Передайте исследователю [стартовый промпт](../prompts/start.md), подготовленный кейс, открытый train и необходимые submit-доступы. Метрика и её окружение заморожены: не заменяйте пакет, модель, зависимости или образ в работающей кампании. Если обнаружилась ошибка измерителя, остановите кампанию и разберите её с оператором; переименование и удаление состояния не дают новой private-попытки.

## Данные и права

Исследовательский контейнер `researcher` с профилем `train` получает разрешённый train и метаданные кампании. Public и private оцениваются на доверенном узле: для public исследователь получает только score, для private — только статус, включая завершённый финал. Результаты private доступны оператору. Исследователь не получает операторский SSH, Docker daemon, закрытые каталоги или журналы модели.

Копируйте `deploy/operator.env.example` в `/etc/arena/operator.env` вне checkout. Env содержит настройки и пути, ключи хранятся отдельно. Не передавайте операторский env исследовательскому контейнеру. Закрытые данные не должны попадать в Docker build context и Git.

| Путь по умолчанию | Содержимое и права |
| --- | --- |
| `/srv/arena/train` | Чистая исследовательская копия, разрешённый train, результаты; UID 10001 может писать |
| `/srv/arena/private/dataset.jsonl` | Закрытый JSONL: `id`, `input`, необязательный `reference`; только оператор и evaluator |
| `/srv/arena/metric` | Полный замороженный пакет метрики с `metric.lock.json`; читает UID 10001, read-only |
| `/srv/arena/state` | Постоянный закрытый журнал и результаты; владелец UID 10001, режим 0700 |
| `/srv/arena/usage` | Учёт модельных вызовов решателя и собственных команд метрики; UID 10001, режим 0700, доступ только evaluator и gateway |
| `/srv/arena/assets` | Только разрешённые всем кандидатам материалы; каталоги 0755, файлы 0644, read-only |
| `/srv/arena/secrets/submit-token` | Непустой случайный bearer token API; читает UID 10001 |
| `/srv/arena/secrets/model-api-key` | Ключ внутренней модели, если она используется; не передаётся runner |

Ограничьте проход в закрытые каталоги. Пакет метрики монтируется целиком read-only; входной JSONL и секреты монтируются отдельными файлами с доступом для UID 10001. Для модельного API без авторизации в Compose создайте пустой файл model-api-key. Если решатель и оценка полностью программные, модельный сервер и ключ не нужны: используйте запуск без gateway ниже. Общий Compose всё же создаёт gateway; в таком режиме ему нужен пустой файл ключа, но обращения к модели отсутствуют. Submit token даёт только отправку и чтение разрешённого результата API, без административных операций.

`ARENA_STATE_DIR` и `ARENA_ASSETS_DIR` — абсолютные пути, одинаковые внутри evaluator и на Docker-хосте. Они передаются daemon для mounts; замена container path на `/state` сломает связь. Docker daemon работает на том же узле. Не используйте сетевой Docker context или SSH `DOCKER_HOST` для этого Compose.

`ARENA_USAGE_DIR` нужен модельным решателям и собственным командам метрики с `uses_model: true`, включая агрегацию. Не помещайте его в assets или workspace и не монтируйте в runner. Для каждого решения создаётся отдельный идентификатор учёта; gateway принимает зарегистрированные обращения и сохраняет расход подготовки и повторов. Ресурсы из stdout кандидата не используются. Решение без модели запускается без сети и получает доверенный полный учёт нулевых токенов; его время всё равно измеряется.

Assets — неизменяемый снимок кампании с зафиксированным digest. Оценщик сохраняет путь, но не пересчитывает большие внешние ресурсы. Read-only mount не защищает от изменений на хосте. `ARENA_DOCKER_GID` задаётся фактической группой сокета (`stat -c '%g' /var/run/docker.sock`), `ARENA_DOCKER_SOCKET` — его путём. Socket получает только evaluator.

## Конфигурация кампании

| Переменная | Значение |
| --- | --- |
| `ARENA_SPLIT` | `private` или `public`; отдельный сервис и хранилище для каждой закрытой части |
| `ARENA_FINALISTS` | Точное положительное число кандидатов в единственном private-пакете, без предела пять |
| `ARENA_OUTPUT_COUNT` | Точное число лучших решений private, от 1 до `ARENA_FINALISTS` |
| `ARENA_USES_MODEL` | Использует ли харнес по умолчанию модель: `true` или `false` |
| `ARENA_RUNNER_IMAGE` | Неизменяемый digest образа харнеса по умолчанию |
| `ARENA_HARNESSES` | JSON-реестр дополнительных доверенных харнесов |
| `ARENA_PARAMETERS` | Фиксированные параметры запросов модели; не параметры эволюции харнеса |
| `ARENA_MAX_BODY_BYTES` | Транспортный предел размера пакета; при больших пакетах настраивается отдельно от числа решений |
| `ARENA_RELEASE_ID` | Идентификатор замороженных условий; смена ID не открывает новую private-попытку |

Модель и параметры её запросов фиксируются до кампании и совпадают у решателя и LLM-судьи. Они не требуются, если ни решение, ни метрика не используют модель. Код обычной программы может оцениваться LLM-судьёй, а модельное решение — вычисляемой метрикой.

`ARENA_METRIC_PATH` указывает на каталог замороженного пакета. Compose монтирует его в `/private/metric` и передаёт этот путь evaluator. Внутри `metric.json` поле `kind` выбирает встроенный модельный профиль или операторскую команду, `direction` — `maximize` или `minimize`; необязательная `aggregation` задаёт собственный итоговый расчёт по набору. Для команды можно указать переносимый `argv`, например `["python", "score.py"]`. Загрузчик находит интерпретатор в окружении evaluator, разрешает локальные пути пакета и закрепляет hashes. `metric.lock.json` проверяет всё содержимое пакета. Установленные внешние зависимости закрепляются образом и lock-файлами окружения.

Команда может быть полностью программной (`uses_model: false`) либо обращаться к модели (`uses_model: true`). Модельной команде арена выдаёт ограниченный gateway URL, имя зафиксированной модели и таймаут; ключ upstream не передаётся. Та же возможность есть у команды агрегации. Любая схема судейства реализуется внутри подготовленной команды; встроенный `kind: llm` — лишь готовый профиль с настраиваемым `votes`. Исполняемая метрика является доверенным операторским кодом, а не кандидатским плагином в песочнице. Формат описан в [правилах оценки](../common/public-evaluation.md).

Старый `ARENA_METRIC_PATH=/srv/arena/private/metric.json` также допустим: Compose смонтирует этот файл по `/private/metric`, а загрузчик прочитает прежний JSON с закреплёнными абсолютными командами. Для новых кампаний используйте целый пакет. Не переводите активную кампанию на новый формат и не обновляйте runtime посреди серии; сохранённая конфигурация защищена от изменений.

Статическая конфигурация модельного судьи проверяется при создании приложения, до допуска private: endpoint, запрещённые параметры запроса и JSON без NaN. Каждая проверка получает отдельный счётчик обращений судьи. Программная метрика не требует модельного клиента. Собственная модельная команда также проверяет настройки до допуска, а её обращения и агрегация учитываются отдельно от решателя через gateway. Ошибки команды метрики и агрегации сохраняют в закрытых `details` и `record.json` код завершения, признак таймаута и ограниченные stdout/stderr. Эти сведения доступны только оператору; API не раскрывает их.

Промпт кампании задаёт допустимые изменения: фиксированный харнес при эволюции решения либо поиск среди харнесов и их параметров при фиксированном решении. Реестр замораживается до запуска. Пример его формы:

```json
{"program":{"image":"sha256:<digest>","uses_model":false,"network":"none"},"agent":{"image":"sha256:<digest>","uses_model":true,"network":"arena-runners"}}
```

`solution.json` кандидата выбирает зарегистрированный ID и передаёт параметры адаптеру; произвольные образы и mounts не принимаются. Один и тот же пакет проверяется в одинаковой конфигурации на всех split. Протокол и комплектный runner описаны в [контракте](../common/runner-contract.md) и [runner/README.md](../runner/README.md).

Соберите операторский runner отдельно и укажите digest. Изменяемые теги оценщик отвергает. Для локального образа получите ID:

```bash
docker image inspect arena-runner:local --format '{{.Id}}'
```

Зафиксируйте также базовые образы по digest. Dockerfile устанавливает зависимости из `uv.lock` через `uv sync --frozen`; теги базовых образов в шаблоне остаются выбором оператора.

Клиент ограничивает размер файлового пакета отдельно: `--max-bundle-bytes` или `ARENA_MAX_BUNDLE_BYTES` (по умолчанию 72 MiB). При большом числе финалистов согласуйте этот предел с `ARENA_MAX_BODY_BYTES` сервиса и reverse proxy.

Лимит поиска — число предложенных решений в [журнале кампании](../common/search-history.md). Env оценщика не устанавливает токенный бюджет поиска. Неудачные решения входят в счётчик и сохраняются. Команда остановки прекращает новые решения и проверки, дожидается начатых и переводит кампанию к отбору по имеющимся результатам.

## Длительная работа

Интервалы задаются в секундах: конечные положительные значения, для задержки повторов допустим ноль. Модельный запрос имеет первую попытку и до пяти повторов при ошибке с теми же входом и настройками. Валидный низкий результат не повторяется. Паузы по умолчанию — 30, 60, 120, 240 и 300 секунд.

| Переменная | По умолчанию | Что ограничивает |
| --- | --- | --- |
| `ARENA_MODEL_TIMEOUT` | `21600`, 6 часов | Одну попытку решателя или судьи |
| `ARENA_RETRY_DELAY` | `30` | Первую задержку повтора, последующие удваиваются до 300 секунд |
| `ARENA_PREPARE_TIMEOUT` | `172800`, 48 часов | Подготовку комплектного раннера |
| `ARENA_RUNNER_TIMEOUT` | `604800`, 7 суток | Решение одного примера, включая подготовку и повторы |
| `ARENA_EVALUATOR_TIMEOUT` | `3600`, 1 час | HTTP-запрос клиента, не всю серию |

Комплектный runner ждёт gateway дольше шести попыток и пауз: при этих настройках 130410 секунд. В gateway таймаут ограничивает всю попытку, у судьи — сетевые операции HTTP-клиента. Внешний лимит runner должен покрывать подготовку и все вызовы харнеса. Эти таймауты защищают от зависания и не ограничивают общий токенный бюджет или длительность кампании.

Reverse proxy, модельный сервер, очередь и среда агента должны допускать эти длительности. Увеличьте время жизни субагентов и глубину вложенности, если среда это поддерживает. Ожидание описано в [правилах долгих запусков](../common/long-runs.md).

Модельный сервер возвращает достоверный `usage`. Успешный ответ без usage некорректен и повторяется; после обрыва без usage расход неизвестен, а не нулевой. Решатель и судья учитываются раздельно. При равном качестве сравниваются ресурсы решателя по [общему правилу](../common/public-evaluation.md).

## Закрытый сервис с модельным gateway

После настройки env:

```bash
docker compose --env-file /etc/arena/operator.env --profile private config --quiet
docker compose --env-file /etc/arena/operator.env --profile private build
docker compose --env-file /etc/arena/operator.env --profile private up -d
```

Профиль Compose `private` обозначает доверенную инфраструктуру; режим API определяется `ARENA_SPLIT`. Compose публикует evaluator на `127.0.0.1:8080`; gateway порты не публикует. `/healthz` проверяет процесс, а не доступность модели. Для удалённой отправки настройте TLS reverse proxy с подходящими пределами тела и времени запроса либо ограниченный туннель к одному API-порту. Исследователю не выдаётся SSH-ключ оператора.

Сеть worker является `internal`: только gateway и краткоживущие runner. Evaluator подключён к `backend`. Проверьте firewall: worker не должен достигать служб хоста, других Docker-сетей, интернета или модельного upstream в обход gateway. Backend имеет выход только к разрешённому внутреннему API; Compose сам firewall хоста не настраивает.

Для public создайте отдельный env с `ARENA_SPLIT=public`, закрытым public JSONL, отдельными state, usage, токеном, release ID, портом и именем runner-сети. Запускайте его с отдельным `--project-name arena-public`. Явные `network` модельных профилей в `ARENA_HARNESSES` должны указывать на сеть этого сервиса, не соседнего private-развёртывания. Public принимает ровно одного кандидата за запрос, запускает отдельного работника до ответа `202` и отдаёт только score. Независимые запросы выполняются параллельно без очереди в общем пуле; `evaluation_id` из submit передаётся клиенту `status --evaluation-id`. Пустой public не требует сервиса. Private принимает один неизменяемый пакет точного размера и возвращает только статус. Выбранные `ARENA_OUTPUT_COUNT` решения и рейтинг хранятся у оператора.

После исчерпания повторов серия получает `failed`; API продолжает работать. После прерывания процесса активная серия также становится `failed`. Идентичная доставка возвращает сохранённое состояние, не запускает повторно. Автоматического продолжения после рестарта и API retry/reset нет. Оператор разбирает причину в закрытом журнале, не раскрывая частичные результаты.

Не удаляйте private state и не переименовывайте кампанию, чтобы отправить изменённый пакет на тот же holdout. Сохраняйте историю допусков при переносе сервиса. Для первого приёмочного запуска используйте искусственные данные: проверьте изоляцию, учёт ресурсов, идемпотентность, сохранение допуска после рестарта и отсутствие закрытых деталей в API. Тесты репозитория не проверяют сеть конкретного Docker-хоста.

## Сервис без модели

Когда решатель и метрика не используют LLM, gateway и ключ модели не нужны. На доверенном узле с Docker и установленными зависимостями запустите evaluator с операторскими переменными окружения. В отличие от Compose, процесс читает `ARENA_TOKEN_FILE`, а не переменную пути монтирования `ARENA_SUBMIT_TOKEN_FILE`:

```bash
ARENA_DATASET_PATH=/srv/arena/private/dataset.jsonl \
ARENA_METRIC_PATH=/srv/arena/metric \
ARENA_STATE_DIR=/srv/arena/state \
ARENA_TOKEN_FILE=/srv/arena/secrets/submit-token \
ARENA_RUNNER_IMAGE='sha256:<replace-with-image-digest>' \
ARENA_RELEASE_ID=replace-with-frozen-release-id \
ARENA_USES_MODEL=false \
ARENA_RUNNER_NETWORK=none \
ARENA_MODEL='' \
ARENA_MODEL_BASE_URL='' \
ARENA_SPLIT=private \
ARENA_FINALISTS=5 \
ARENA_OUTPUT_COUNT=1 \
uv run python -m evaluator
```

Замените digest и числа на условия кампании. Пакет метрики должен быть заморожен и доступен процессу, его внешние зависимости установлены в том же закреплённом окружении. Для длительной службы используйте доступный на узле менеджер процессов. Процесс слушает порт 8080; доступ ограничивает операторская сеть или reverse proxy.

## Исследовательский контейнер

`ARENA_TRAIN_WORKSPACE` содержит чистую копию с разрешённым train, без операторского env, закрытого state, токенов модели или ссылок на закрытые материалы. Простой mount текущего каталога оператора не подходит. Необходимый CLI-харнес оператор добавляет в свой image либо работает из ограниченного чата.

```bash
docker compose --profile train build researcher
ARENA_TRAIN_WORKSPACE=/srv/arena/train docker compose --profile train run --rm researcher
```

Исследователь видит свой workspace и разрешённую сеть. Доступ к внутренней модели для train настраивается отдельно; закрытый gateway ему недоступен. Модельные вызовы с данными направляются только внутренним моделям; не передавайте данные облачному чату-оркестратору. Ограничение egress задаёт инфраструктура оператора.

Общий MLflow настраивается через `ARENA_MLFLOW_URL`. Его доступность и права проверяет оператор. Правила экспорта train и public-score описаны в [MLflow](../common/mlflow.md); private автоматически туда не отправляется.
