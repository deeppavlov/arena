# Транспорт и сервер MLflow

[operator-nginx.conf](operator-nginx.conf) — общий конфиг nginx для операторского MLflow. Compose кейсов подключают этот файл, не создавая своих копий. Он передаёт запросы к сетевому alias `operator-source:5000` с фиксированным Host `localhost:5050`, удаляет Authorization и не ведёт access log. Доступ ограничивается операторской сетью; этот proxy нельзя подключать к исследовательской сети или публиковать для неё.

Тела запросов и ответов передаются потоком: `proxy_request_buffering off`, `proxy_buffering off`, `proxy_http_version 1.1`. Явный HTTP/1.1 нужен для потоковой передачи chunked-запросов в nginx 1.28. Proxy не накапливает тела артефактов в `/tmp` на tmpfs; предел HTTP-тела остаётся 256 MiB. Лимиты памяти, сети и тома задаёт Compose установки.

При подготовке release сохраняйте путь `deploy/mlflow/operator-nginx.conf` относительно корня исходников. Все три существующих Compose подключают его через относительный путь к корню release. Проверка `tests/test_mlflow_deploy.py` разбирает Compose и проверяет readonly mount общего файла; новый потребитель должен быть включён в этот тест.

## Экспорт крупных записей

Потоковый proxy не решает ограничения одного большого HTTP-запроса и память, которую MLflow тратит на разбор трейсов. Экспортёр Arena сохраняет JSON больше 8 MiB бинарными частями не больше 8 MiB; прежний путь артефакта содержит manifest версии 1. Он проверяет части чтением обратно до публикации manifest. Крупные списки вызовов разбиваются на отдельные трейсы, а span с payload больше 1 MiB ссылается на полный артефакт вызова. Небольшие записи сохраняют прежнее представление. Формат, восстановление через `read_json_artifact` и повтор доставки описаны в [common/mlflow.md](../../common/mlflow.md).

Экспортёр сериализует полный JSON во временный файл, поэтому `TMPDIR` должен указывать на доступный для записи дисковый том. Для Docker-монитора установки используйте `<ARENA_ROOT>/operator/state/research-monitor/tmp` с владельцем UID 10001 и достаточным местом. `/tmp` на tmpfs переносит этот объём в расход памяти контейнера; разбиение HTTP-запросов этого не исправляет. Явно заданный недоступный `TMPDIR` приводит к ошибке экспорта с сохранением очереди.

В конфигурациях общего сервера MLflow лимит 4 GiB сочетается с явным `--workers 1`, чтобы несколько workers не дублировали расход памяти. Эти параметры дополняют ограничение размера публикуемых трейсов и проверяются на синтетическом экспорте. При изменении сервера сохраняйте backend/artifact volumes. Обновление его контейнера не требует перезапуска оценщиков или исследователя; локальные очереди обеспечивают повтор доставки после временной недоступности.

Отдельный монитор может быть единственным отправителем: оценщики с `ARENA_TRACKING_DELIVERY=queued` сохраняют очередь, монитор доставляет её. Порядок независимого обновления образа монитора и работы с уже запущенными оценщиками описан в [интеграции Docker](../../integrations/docker/README.md); адреса и firewall принадлежат конфигурации кейса.

## Проверка транспорта

Перед передачей изменений этого конфига или развёртывания выполните из корня репозитория:

```bash
uv run pytest tests/test_mlflow_deploy.py
uv run python tests/mlflow_proxy_smoke.py
```

Контейнерная проверка использует отдельную внутреннюю Docker-сеть, синтетический HTTP-сервер и настоящий nginx с лимитом памяти 128 MiB. Она передаёт 160 MiB с chunked encoding, читает ответ потоком, сравнивает содержимое и проверяет отсутствие OOM. Настоящие MLflow, модели, датасеты и кампании не используются. Эта проверка запускается отдельно от обычного pytest и требует доступного Docker daemon и локальных образов `nginx:1.28-alpine`, `python:3.12-slim`; при отсутствии заранее загрузите их через `docker pull`. Образы можно явно передать через `--nginx-image` и `--python-image`; сам сценарий их не загружает.

## Проверка полного экспорта

При изменениях экспортёра или серверной конфигурации дополнительно выполните:

```bash
uv run python tests/mlflow_export_smoke.py
```

Проверка запускает настоящий MLflow 3.16.0 с одним worker и лимитом 4 GiB, nginx с лимитом памяти 128 MiB и HTTP-тела 256 MiB, а также клиент с лимитом 4 GiB и дисковым `TMPDIR`. Используются отдельные внутренняя сеть и тома, синтетические данные без моделей и кампаний. По умолчанию выполняются три сценария: `aggregate` передаёт совокупную запись больше 256 MiB, `singleton` — отдельный вызов больше 256 MiB, а `sdk_payloads` — 65 вызовов с 21 вариантом строк, JSON, вложенных типов и встроенных image/audio payload. Проверяются полное восстановление записи и payload вызовов, исходные связи и времена, подтверждение `arena_export_complete`, повтор с теми же run/trace ID, фактические размеры HTTP-запросов и показатели памяти/OOM. В `sdk_payloads` дополнительно проверяются исходные строки и типы в записи, очереди и каждом артефакте вызова, ожидаемое представление SDK, сохранность data URI и структурированных вложений, восстановление окружения после временного отключения извлечения attachments. Эта проверка дополняет proxy smoke, который проверяет потоковую передачу без SDK и сервера MLflow.

Нужны Docker daemon и локальные образы `ghcr.io/mlflow/mlflow:v3.16.0` и `nginx:1.28-alpine`; сценарий использует `--pull never`. SDK работает внутри образа MLflow, на хосте достаточно стандартной библиотеки Python. Можно передать `--image`, `--nginx-image`, выбрать отдельные сценарии через `--cases`, например `--cases sdk_payloads`, и сохранить безопасный JSON-отчёт через `--output <path>`. Успех синтетической проверки не заменяет проверку доставки очередей и чтения payload через разрешённый доступ в целевой установке.

## Применение изменений

Если меняется только proxy, после проверки транспорта оператор выполняет `nginx -t` в целевом окружении и применяет Compose только к `operator-tracking` с `--no-deps --pull never`. Исследователь, оценщики, монитор и backend MLflow для изменения proxy не требуют перезапуска. Для обновления экспортёра отдельно обновляется монитор; изменение `--workers` применяется к серверу с прежними томами. Сохраняйте локальные очереди и дождитесь штатной доставки; подтверждение завершения экспорта проверяется на сервере MLflow. Не повторяйте решения или оценивание ради доставки.
