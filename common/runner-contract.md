# Фиксированный харнес и кандидат

Оператор закрепляет образ харнеса по `sha256` до кампании. Public и private используют один и тот же харнес, модель и параметры. Кандидат не выбирает образ, команды контейнера, mounts, модель или адрес её сервера через API.

Для каждого private-примера оценщик создаёт новый контейнер. В нём:

- `/candidate` — readonly-файлы ровно замороженного пакета;
- `/assets` — необязательные readonly-материалы, разрешённые всем решениям;
- `/tmp` — ограниченная временная память;
- stdin — JSON с `input`, фиксированной `model`, адресом `model_base_url` вида `http://model-gateway:8081/runs/<run_id>/v1` и таймаутами в секундах `model_request_timeout`, `prepare_timeout`;
- stdout — один JSON `{"answer":"окончательный ответ"}` размером не более 1 MiB.

Ненулевой exit, timeout, переполнение или неверный JSON означают сбой выполнения: закрытая серия останавливается без публикации частичного результата. Штатный JSON собственного харнеса с пустым окончательным ответом — сгоревший ответ с оценкой 0. Пустой или обрезанный ответ самого модельного API считается ошибкой обращения и сначала проходит до пяти повторов.

Эталон, соседние примеры, оценки, секреты и private-логи контейнеру не передают. Сеть по умолчанию отключена. Для модельного харнеса разрешена только выделенная внутренняя сеть с gateway, который пропускает вызовы фиксированной модели. В эту сеть не входят оценщик, публичный исследователь и MLflow.

## Комплектный пример

`runner/main.py` показывает минимальный фиксированный харнес: читает `/candidate/prompt.md`, при наличии запускает `/candidate/prepare.py`, затем запрашивает один корректный ответ внутренней модели. При технической ошибке gateway выполняет до пяти повторов с тем же запросом. `prepare.py` получает через stdin JSON с `input`, `assets_dir: "/assets"`, `model`, `model_base_url` и `model_request_timeout`, затем возвращает JSON `{"context":"дополнительный контекст"}`. Модельные вызовы при подготовке идут через переданный gateway с учётом токенов и теми же повторами; клиент использует переданный таймаут. Скрипт выполняется только внутри одноразового контейнера. Сам приватный оценщик этот код не импортирует.

По умолчанию одна модельная попытка может длиться до шести часов, подготовка — до 48 часов, весь запуск одного примера — до семи суток. HTTP-ожидание runner покрывает все шесть попыток gateway, паузы и запас на передачу результата. Для другого харнеса оператор согласует эти пределы до кампании; клиентские таймауты не должны обрывать допустимые повторы. Настройки описаны в [развёртывании](../deploy/README.md), поведение исследователя — в [правилах долгих запусков](long-runs.md).

Ресурсы решения измеряются обязательно. Время фиксирует доверенный runner снаружи контейнера, включая подготовку и повторы. Токены всех запросов учитывает gateway по usage модельного сервера в закрытом журнале конкретного запуска; утверждения кандидата о своём расходе не используются. Успешный ответ без корректного usage считается ошибкой запроса. Для неудачных попыток без usage сохраняется явный счётчик `unreported_attempts`; известный расход в таком замере является нижней границей. Измерения судьи хранятся отдельно.

Этот пример не ограничивает способы решения RAG, файловым поиском или конкретным агентом. Для Hermes или другого уже используемого харнеса оператор собирает собственный образ с тем же stdin/stdout-протоколом. Новая версия адаптера означает новую конфигурацию кампании, а не незаметную замену харнеса.

Изоляция процесса не доказывает научную корректность кандидата: ревьюер дополнительно проверяет допустимую область изменений и отсутствие подгонки под конкретные публичные ответы.
