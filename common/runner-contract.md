# Фиксированный харнес и кандидат

Оператор закрепляет образ харнеса по `sha256` до кампании. Public и private
используют один и тот же харнес, модель и параметры. Кандидат не выбирает
образ, команды контейнера, mounts, модель или адрес её сервера через API.

Для каждого private-примера оценщик создаёт новый контейнер. В нём:

- `/candidate` — readonly-файлы ровно замороженного пакета;
- `/assets` — необязательные readonly-материалы, разрешённые всем решениям;
- `/tmp` — ограниченная временная память;
- stdin — JSON `{"input":"текущая задача","model":"фиксированная модель","model_base_url":"http://model-gateway:8081/v1"}`;
- stdout — один JSON `{"answer":"окончательный ответ"}` размером не более 1 MiB.

Ненулевой exit, timeout, переполнение или неверный JSON означают сбой
выполнения: закрытая серия останавливается без публикации частичного результата.
Штатный JSON с пустым ответом — сгоревший ответ с оценкой 0.

Эталон, соседние примеры, оценки, секреты и private-логи контейнеру не передают.
Сеть по умолчанию отключена. Для модельного харнеса разрешена только выделенная
внутренняя сеть с gateway, который пропускает вызовы фиксированной модели.
В эту сеть не входят оценщик, публичный исследователь и MLflow.

## Комплектный пример

`runner/main.py` показывает минимальный фиксированный харнес: читает
`/candidate/prompt.md`, при наличии запускает `/candidate/prepare.py`, затем
делает один вызов внутренней модели. `prepare.py` получает через stdin JSON
`{"input":"текущая задача","assets_dir":"/assets"}` и возвращает JSON
`{"context":"дополнительный контекст"}`. Он выполняется только внутри
одноразового контейнера. Сам приватный оценщик этот код не импортирует.

Этот пример не ограничивает способы решения RAG, файловым поиском или
конкретным агентом. Для Hermes или другого уже используемого харнеса оператор
собирает собственный образ с тем же stdin/stdout-протоколом. Новая версия
адаптера означает новую конфигурацию кампании, а не незаметную замену харнеса.

Изоляция процесса не доказывает научную корректность кандидата: ревьюер
дополнительно проверяет допустимую область изменений и отсутствие подгонки
под конкретные публичные ответы.
