# Подготовка SC-35 к арене

28 октября 2026 года по команде пользователя подготовлен кейс из `archive/local/sc-35-espd`. Исходная ревизия арены — `c7333babe0bc38d3d6e7f1ebf2b1dd5d230c53e0`; изменения оставлены в рабочей копии без коммитов. Условия кампании находятся в `cases/sc35/campaigns/sc35-first-20261028/campaign.md`, фактическая готовность установки — в её `preparation.md`.

## Состав изменения

В `cases/sc35` перенесены детерминированная метрика, исходный baseline, общие нормативные материалы, схема ответа, proposal и описание задачи. Сборщик и экспортер исходного пакета воспроизвели 881 вход, 1 067 замечаний и 28 контролей с прежним split 113/128/640. JSONL переданы отдельно в операторское хранилище GPU6; закрытое содержимое не выводилось и в новый кейс не копировалось. Изменений данных, таксономии и формулы оценки нет.

Исполняемый пакет метрики сохранён без изменения формулы: суммирование символьных статистик по категориям, затем macro F1 на всём наборе. Командные этапы оценки и агрегации не используют модель. Пакет заморожен штатным `evaluator.prepare` в каталоге кампании; `freeze` и `verify` проверили девять файлов. Смысл метрики отдельно проверен на синтетических примерах, включая отличие корпусной агрегации от среднего F1 отдельных примеров.

SC-35 использует собственный адаптер входного DOCX и переиспользует закреплённые runtime, профиль и исследовательский launcher Hermes из SC-71. Агентский решатель получает пути к DOCX и исходному envelope; base64 не включается в его начальное модельное сообщение. Исходный программный baseline с содержательным модельным этапом подключён вторым харнесом `sc35-content`. Изоляция, учёт ресурсов, train API и private gate используют общее ядро арены.

Из переносимого runtime исключены неиспользуемый инвентарь ссылок из GOLD и генератор эталонов; оставлен только необходимый helper записи JSON. Импорт необязательного `pypdf` перенесён в PDF-ветку, чтобы DOCX-путь работал с объявленными зависимостями. Лимит сериализованного ответа теперь учитывает завершающий перевод строки. Оба исправления проверены на синтетике. Общие механизмы арены и работающие установки SC-71 не менялись.

## Проверки

Прошли `uv run ruff check .`, `uv run pyright` без ошибок и предупреждений, `uv run pytest` — 1629 тестов, `uv run python -m evaluator.smoke`. Проверки нового кейса с закреплёнными `lxml==6.1.3` и `jsonschema==4.26.0` — 32 теста. Независимое ревью пакета, адаптера и конфигурации не обнаружило блокеров для заморозки. Живая синтетическая HTTP-приёмка подтвердила ожидаемый score 100, раздельный учёт расходов, завершение измерения в отдельном журнале и чтение полного MLflow payload из исследовательской сети. Проверены права UID, сетевые запреты, private gate 100/10/3 и пустой журнал настоящей кампании. Свидетельства сохранены в `archive/cases/sc35/campaigns/sc35-first-20261028`.

Первая сборка базового evaluator на GPU6 остановилась из-за отсутствовавшего `cases/template` в контексте legacy Docker, который обрабатывает промежуточную стадию researcher. После передачи разрешённого шаблона повторная сборка завершилась успешно. В рабочих контекстах сборки отсутствуют архив, реальные данные и секреты.

Подготовка не регистрирует решения в журнале настоящей кампании и не запускает поиск. Все модельные ответы при технической приёмке подставные; качество методов на реальных документах этим этапом не измеряется.
