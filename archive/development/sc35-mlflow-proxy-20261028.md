# Исправление операторского MLflow proxy SC-35 28 октября 2026 года

Пользователь попросил исправить MLflow после проверки состояния работающей кампании `sc35-first-20261028`. Операторский nginx перезапускался из-за OOM: крупные тела запросов MLflow буферизовались в `/tmp` на tmpfs при лимите памяти 128 MiB. До исправления зафиксирован 321 рестарт; два экспорта оставались в локальной очереди. Исследователь, оценщики, оба gateway и оба backend MLflow продолжали работать.

В [Compose кампании](../../cases/sc35/campaigns/sc35-first-20261028/deploy/mlflow-compose.yaml) операторский proxy первоначально переведён с общего SC71-конфига на отдельный конфиг SC35; последующее общее исправление перенесло его в [deploy/mlflow/operator-nginx.conf](../../deploy/mlflow/operator-nginx.conf). Отключены буферизация запросов и ответов, явно включён HTTP/1.1 для потоковой передачи chunked-запросов. Память 128 MiB, предел тела 256 MiB, сетевые границы, UID, фиксированный Host и очистка Authorization сохранены. При первоначальном исправлении конфигурация SC71 не менялась. Поведение директив описано в [официальной документации nginx](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_request_buffering).

На GPU6 проверены `nginx -t` и Compose, затем пересоздан только `operator-tracking` с `--no-deps --pull never`. Новый proxy начал работу в 18:10:43 МСК. Синтетический артефакт 160 MiB загружен с chunked encoding и прочитан потоком через операторский proxy: оба HTTP-ответа 200, содержимое побайтово совпало, передача заняла 4,664 секунды. Проверка не вызывала модели и не регистрировала решений кампании. Диагностический MLflow experiment — `6`, run — `9ccca38e17cf4bf7b6a09bf21a98c8d8`.

В 18:13:24 МСК у нового proxy не было рестартов и OOM; пик памяти после передачи составил 6 090 752 байта при прежнем лимите 134 217 728 байт. ID, время старта и счётчики рестартов остальных десяти проверенных контейнеров сохранились. Образ не загружался повторно; `nginx -t` использовал точный image старого контейнера, а итоговый image ID совпал с историческим свидетельством подготовки того же proxy.

В 18:13:59 МСК штатный монитор завершил доставку отложенных экспортов: все семь очередей вернули `status=ok`, `errors=0`, `pending=0`. В 18:16:48 МСК сервер MLflow подтвердил оба соответствующих run как `FINISHED`, с `arena_export_complete=true`, `arena_execution_status=FINISHED` и операторской видимостью. Проверены только метаданные, закрытые артефакты и трейсы не читались. Каждый экспорт до успеха имел 23 неудачные попытки доставки; сами решения и оценка не повторялись, второй процесс flush не запускался. Итоговый пик памяти proxy составил 6 590 464 байта, рестарты и OOM остались нулевыми. Локальные записи, журнал, условия, модель, метрика и разбиение данных сохранены. [Свидетельство исправления на GPU6](../cases/sc35/campaigns/sc35-first-20261028/evidence/mlflow-proxy-repair-20261028.json) содержит безопасные метаданные без payload и закрытых результатов.

Прошли Ruff, Pyright без ошибок и предупреждений, 1629 тестов ядра, smoke и 32 теста SC35. Единственное предупреждение pytest — прежнее StarletteDeprecationWarning о httpx. [Результаты проверок](../cases/sc35/campaigns/sc35-first-20261028/evidence/mlflow-proxy-checks-20261028.json). Коммитов нет.
