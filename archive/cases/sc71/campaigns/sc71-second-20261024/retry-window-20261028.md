# Отложенное увеличение окна повторов

28 октября пользователь поручил увеличить сумму пауз перед пятью повторами до получаса, сохранив возрастающие интервалы и первый короткий повтор. Работающую арену не останавливать; подготовленный код применить при следующем возобновлении после недоступности модели. Это изменение технических ожиданий, а не модели, метрики, split или числа попыток.

Прежние паузы: 30, 60, 120, 240, 300 секунд, сумма 750 секунд. Новые: 30, 90, 240, 540, 900 секунд, сумма 1800 секунд. Без учёта длительности запросов повторные попытки приходятся на 00:30, 02:00, 06:00, 15:00 и 30:00 после первой. Клиентский таймаут увеличен с 130410 до 131460 секунд: шесть попыток по 21600 секунд, все паузы и 60 секунд запаса. Успешный ответ не повторяется.

Пакет GPU6: `/cephfs/home/malyshev_sa/arena-sc71-second-20261024/operator/pending/retry-20261028/`. Он содержит изменённые исходники, два Dockerfile, отдельный Compose override и свидетельство подготовки. Активные `images.env`, Compose, credentials, workspace и состояние кампании при подготовке пакета не изменяются. Образы, реально используемые контейнерами, импортируют код из `/opt/arena`, а не из host release.

Для следующего возобновления после сбоя внешнего исследователя:

1. Проверить терминальное состояние исследователя, ноль активных запросов его старого scope, сохранение terminal manifest и экспорта. Закрытый scope не открывать повторно.
2. Применить подготовленный override только к `researcher-gateway` и `researcher`; остальные сервисы не пересоздавать. Новые образы основаны на прежних закреплённых образах и меняют только расписание повторов и согласованные клиентские таймауты. Не заменять общий `ARENA_EVALUATOR_IMAGE`: это затронет оценщики.
3. Сохранить прежние active/access, журнал, файлы кампании и передачу контекста; создать новый usage scope с прежней моделью и параметрами. Для клиента использовать `model_request_timeout=131460`. Пока новый контейнер не создан, active содержит новый run ID без container ID; затем записать полный фактический ID, чтобы монитор не закрыл scope по старому завершённому контейнеру.
4. Повторить живой private readiness, чтение разрешённого синтетического train-трейса и проверку состояния журнала. Продолжить тот же поиск, без сброса предложений, ответов, оценок, build-квитанций и private-допуска. Проверить первый успешный запрос исследователя.

Такое возобновление применяет новый график только к внешнему исследователю. Для решателей и судей код уже исправлен в проекте; обновление `model-gateway` и оценщиков проводится отдельно при отсутствии выполняющихся проверок. Образ решателя и зафиксированную provenance нельзя менять незаметно вместе с внешним исследователем. Текущие проверки не прерываются ради этого обновления.

Подготовленный пакет не запускает автоматический монитор перезапуска и не меняет уже загруженный код. Датированные параметры действующей кампании описывают установленную версию до применения пакета.

Проверки проекта прошли: Ruff, оба Pyright, smoke, 1629 тестов ядра и 177 тестов SC71. На GPU6 новый образ gateway прошёл синтетическую серию из шести попыток с суммой пауз 1800 секунд; новый Hermes прошёл пять сценариев с подставной моделью. Реальных модельных обращений при этих проверках не было. Образы и подтверждение отложенного применения записаны в [свидетельстве пакета](evidence/retry-window-package-20261028.json).
